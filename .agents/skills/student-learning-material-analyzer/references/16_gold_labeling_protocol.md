# Human Gold Labeling Protocol

Use this protocol before claiming 99% correctness for `analyze_learning_evidence`.

## Required Files Per Case
- De-identified source material retained outside the public eval JSON.
- `VisionEvidencePacket` produced by the OCR/Layout/Vision provider under test.
- `student_learning_material_question_segmentation_review.v0.1` JSON generated from the same VisionEvidencePacket before definitive gold acceptance.
- `student_learning_material_gold_label_package.v0.1` JSON with two independent labels and adjudication.
- `StudentLearningMaterialAnalysis` JSON generated by the provider/model under test.

## Gold Label Package
- Use `fixture_schema: student_learning_material_gold_label_package.v0.1`.
- Keep `case_id` stable across both reviewer labels, adjudication, and dataset entry.
- Set anonymization flags to true only after student, teacher, school, and raw image exposure risks are removed from the gold file.
- Include at least two labels with distinct `reviewer_id` values.
- For each question, include `question_evidence_basis.student_trace_evidence_refs`.
- When `definitive_judgement_allowed=true`, include `expected_correctness` and at least one answer/rubric or teacher-correction evidence reference.
- When `definitive_judgement_allowed=false`, omit `expected_correctness`; the model must route the question to unknown or teacher review.
- If a gold package or annotation import uses `side_input.*` answer/rubric evidence refs, generation and validation must receive the matching question-mapped answer key or rubric side-input file. A bare `side_input.*` ref without the same-question whitelist cannot support human-gold acceptance.
- If reviewer labels disagree on classification, definitive allowance, correctness, knowledge points, or mistake types, add `adjudicated_gold`.

## Commands
- Generate a redacted question-segmentation QA artifact: `XUEMAI_VISION_PACKET=/absolute/path/to/packet.json XUEMAI_QUESTION_SEGMENTATION_REVIEW_OUTPUT=/absolute/path/to/question-segmentation-review.json npm run generate:k12-question-segmentation-review`.
- Generate a non-claimable package draft from a validated VisionEvidencePacket: `XUEMAI_VISION_PACKET=/absolute/path/to/packet.json XUEMAI_QUESTION_SEGMENTATION_REVIEW=/absolute/path/to/question-segmentation-review.json XUEMAI_GOLD_LABEL_TEMPLATE_OUTPUT=/absolute/path/to/gold-label-template.json npm run generate:k12-gold-label-template`.
- Convert a normalized annotation import into a final package: `XUEMAI_GOLD_LABEL_ANNOTATION_IMPORT=/absolute/path/to/annotation-import.json XUEMAI_VISION_PACKET=/absolute/path/to/packet.json XUEMAI_QUESTION_SEGMENTATION_REVIEW=/absolute/path/to/question-segmentation-review.json XUEMAI_GOLD_LABEL_PACKAGE_OUTPUT=/absolute/path/to/gold-label-package.json npm run generate:k12-gold-label-package`.
- Validate one final gold package: `XUEMAI_GOLD_LABEL_PACKAGE=/absolute/path/to/gold-label-package.json npm run validate:k12-gold-labels`.
- Generate the model output artifact: `XUEMAI_VISION_PACKET=/absolute/path/to/packet.json XUEMAI_ANALYSIS_OUTPUT=/absolute/path/to/analysis.json npm run generate:k12-analysis-output`.
- Evaluate the dataset: `XUEMAI_EVAL_DATASET=/absolute/path/to/dataset.json npm run eval:k12-material`.

## Annotation Tool Candidates
- Label Studio can be used as the first-choice human labeling UI for question-level correctness, evidence sufficiency, material classification, mistake type, and feedback-safety labels.
- CVAT can be used for visual-region gold such as question segmentation, bbox/polygon, student answer regions, teacher correction marks, and crop-ref quality review.
- X-AnyLabeling may be used for offline experiments or visual annotation comparison, but its GPL-3.0 license means it should not become the default production dependency without review.
- Tool exports are intermediate files only. First normalize them into `student_learning_material_gold_label_annotation_import.v0.1`, then convert into `student_learning_material_gold_label_package.v0.1` and VisionEvidencePacket-aligned evidence refs before validation.

## Normalized Annotation Import
- Use `fixture_schema: student_learning_material_gold_label_annotation_import.v0.1`.
- Include `case_id`, optional `package_id`, optional `annotation_tool`, anonymization flags, at least two independent labels, and an explicit `adjudication`.
- Each label and adjudication must include `material_classification` plus `questions[]`.
- Each question must include `question_id`, `definitive_judgement_allowed`, optional `expected_correctness`, expected knowledge/mistake labels, and optional evidence refs.
- Evidence refs can point to the VisionEvidencePacket or `side_input.*`; missing evidence refs are inferred from the VisionEvidencePacket only when the matching evidence type exists for that `question_id`.
- `side_input.*` refs are allowed only for answer/rubric basis and only after the same `question_id -> side_input` map is declared via `XUEMAI_ANSWER_KEYS` or `XUEMAI_RUBRICS`.
- When `XUEMAI_QUESTION_SEGMENTATION_REVIEW` is supplied during package generation, any imported question with `definitive_judgement_allowed=true` must have matching segmentation review status `pass`.
- Without anonymization, two labels, adjudication, and packet alignment, the generated package is only a draft and cannot support 99% acceptance.

## Dataset Entry
Dataset cases may reference the adjudicated label package directly:

```json
{
  "gold_label_package_path": "gold/case-001-label-package.json",
  "analysis_path": "outputs/case-001-analysis.json"
}
```

Paths resolve relative to the dataset JSON file.

## Non-Negotiable Gates
- Synthetic labels are smoke tests only.
- A definitive gold judgement requires a matching `pass` entry in the question-segmentation review artifact; uncertain boundaries, low confidence, missing crop refs, or orphan evidence must be labeled as evidence-insufficient / teacher-review expected.
- Generated label templates are annotation drafts only; they must not be used as final gold packages until humans complete anonymization, two independent labels, and adjudication.
- A package without double labeling and adjudication cannot support a 99% claim.
- A package with anonymization flags set to false cannot support a 99% claim.
- A degraded model output can be kept for debugging, but not for acceptance.
