# Student Learning Material Analyzer

## Goal
Build and review the Xuemai student learning material analysis Skill. The Skill turns China K12 tutoring materials with student traces into evidence-linked analysis, teacher-reviewable SkillCards, profile update suggestions, next learning actions, and safe WeChat feedback drafts.

## When To Use
- Use when implementing or reviewing analyze_learning_evidence, learning material upload, OCR evidence ingestion, report generation, profile update suggestions, next lesson actions, or parent feedback based on student materials.
- Use when the input is a China primary, middle, or high school subject tutoring material that contains student answers, corrections, teacher markings, notes, or other student-specific learning traces.
- Use when deciding whether analysis should proceed, degrade, block, or require teacher review because evidence is missing or low confidence.

## When Not To Use
- Do not use for teacher PPT, teacher lesson plans, teacher preparation notes, blank textbooks, blank worksheet templates, or generic teaching resources without student traces.
- Do not use for non-K12, non-subject tutoring scenarios unless the product requirement explicitly extends the scope.
- Do not infer student ability when there is no student answer, correction, teacher marking, or note trace.
- Do not use this Skill to bypass SkillCard review, teacher confirmation, or long-term profile write controls.

## Runtime Architecture
Pipeline:

    Student material upload
    -> file storage and page rendering
    -> external OCR/Layout/Vision plugin
    -> VisionEvidencePacket
    -> provider-agnostic text reasoning model adapter
    -> StudentLearningMaterialAnalysis JSON
    -> teacher review
    -> confirmed archive/profile writeback or draft WeChat feedback

The current default reasoning model is DeepSeek v4 Pro through the shared provider-agnostic model layer. Any replacement model must obey the same boundary: it must not directly analyze images, PDFs, handwriting, teacher corrections, question regions, bbox, or crop_ref. Those must be produced by an external OCR/Layout/Vision plugin as a structured VisionEvidencePacket before the reasoning model is called.

## Required Input
- VisionEvidencePacket with page_id, question_id, evidence_type, confidence, and bbox or crop_ref for visual evidence.
- Text question stems, student answers, teacher corrections, standard answers, scoring rubrics, knowledge point candidates, student history, and teacher preferences when available.
- Explicit material state: valid_student_material, insufficient_student_trace, blank_template, teacher_resource, low_quality, or needs_review.
- Explicit non-K12 or non-mainland-K12 scope signals such as university, adult education, vocational qualification, postgraduate entrance, non-K12 external exams, Hong Kong/Macau/Taiwan exam systems, or international curricula must be detected and routed away from student ability analysis even if material_state is valid_student_material.
- Every upstream evidence item must have a stable evidence_ref that can be shown to the teacher and reused in audit logs.

## Required Output
- StudentLearningMaterialAnalysis JSON matching references/output_schema.md.
- Each correctness judgement, knowledge mapping, mistake diagnosis, profile update suggestion, next action, and WeChat feedback sentence must include evidenceRefs.
- All analysis evidenceRefs must resolve to the same VisionEvidencePacket evidence refs, explicitly question-mapped side input refs, or previous-month source refs only inside `monthly_comparison_seed`.
- `question_analyses` must exactly cover every `VisionEvidencePacket.questions[].question_id` once and in the same order; missing, extra, duplicate, or reordered questions must fail runner/asset preflight.
- Output must separate AI draft from teacher-confirmed facts. Suggestions may be shown in SkillCard, but they must not become student profile facts until teacher confirmation.
- WeChat feedback status must be draft, blocked, or needs_teacher_review before teacher confirmation. It must not be ready_to_send before review.
- Monthly report snapshots emitted by this Skill must remain `teacher_confirmed: false`; the monthly_report workflow may only aggregate copies that were explicitly confirmed by the teacher.
- If `monthly_comparison_seed.previous_month_snapshot` is present, it must include replayable previous-month source `evidenceRefs`; otherwise user-facing monthly notes must state insufficient previous-month evidence and must not write explicit progress/regression trends.
- User-facing report output should be assembled through `src/skills/student-learning-material-analyzer/user-facing-result.ts`; it must expose teacher/UI-facing material classification fields with source labels, and must not expose raw internal `evidenceRefs` in teacher or parent-facing copy.

## Core Workflow
1. Validate material state, explicit K12 scope, and reject unsupported materials.
2. Validate VisionEvidencePacket structure and evidence coverage.
3. Run the deterministic material pre-classifier in `src/skills/student-learning-material-analyzer/material-classifier.ts` to identify material type, subject, stage, grade candidate, and region/curriculum signals with evidenceRefs, including common mainland wording such as 课时作业、周末作业、寒暑假作业、校本作业、晨测、堂清、限时训练、期中/期末复习卷、诊断卷、小升初 and local textbook version names.
4. Run the deterministic per-question evidence gate in `src/skills/student-learning-material-analyzer/question-evidence-readiness.ts`; definitive correctness is allowed only when question segmentation, student answer, same-question answer key/rubric or clear teacher correction, critical evidence region attribution, and confidence are sufficient. External `answerKeys` / `rubrics` can satisfy the answer basis only when explicitly mapped to `question_id`.
5. Run the provider-agnostic text reasoning adapter on structured text evidence only.
6. Produce StudentLearningMaterialAnalysis JSON with evidenceRefs and confidence/degrade reasons.
7. Run schema, evidence coverage, and WeChat safety checks.
8. Render a SkillCard summary and detailed report for teacher review.
9. Allow teacher edit, confirm, reject, or request re-analysis.
10. Write only teacher-confirmed outputs into student long-term records.

## Accuracy Hard Rules
- MUST only analyze China primary to high school subject tutoring materials.
- MUST route explicit non-K12 or non-mainland-K12 materials such as university, adult education, vocational education, postgraduate entrance, CET/IELTS/TOEFL, professional qualification, Hong Kong/Macau/Taiwan exam systems, or IB/A-Level/IGCSE/AP/SAT materials to teacher review/block instead of text reasoning.
- MUST NOT analyze teacher PPT, teacher lesson plans, teacher preparation materials, blank textbooks, or blank test templates as student performance evidence.
- MUST NOT infer student ability without student answer, correction, teacher marking, or note traces.
- MUST route notes-only materials or teacher-mark-only materials to teacher review before model reasoning; they can preserve classification and missing-context hints, but cannot generate formal ability, correctness, parent feedback, profile, or monthly conclusions.
- MUST attach evidenceRefs to every correctness judgement, knowledge mapping, mistake diagnosis, profile update, next action, and WeChat feedback sentence.
- MUST degrade correctness judgement when standard answers, scoring points, or clear teacher correction are missing; external answer/rubric side inputs only count when mapped to the same `question_id`.
- MUST NOT claim method weakness, concept confusion, or carelessness when student process evidence is absent.
- MUST cap or block downstream conclusions when OCR/Layout/Vision confidence is low, critical evidence lacks same-question region attribution, or bbox/crop_ref is missing.
- MUST label error source as vision_plugin_error, answer_key_error, deepseek_reasoning_error, review_ui_error, data_writeback_error, or feedback_safety_error when failures occur.

## Text Reasoning Model Constraints
- The reasoning model MUST NOT directly analyze images or PDFs.
- The reasoning model may only consume VisionEvidencePacket, text question stems, student answers, teacher corrections, standard answers, scoring rubrics, knowledge point libraries, student history, and teacher preferences.
- The reasoning model MUST NOT invent OCR, handwriting content, formula tokens, teacher marks, question regions, bbox, crop_ref, or absent student process.
- The reasoning model output must be structured JSON matching StudentLearningMaterialAnalysis. Long prose can only appear inside allowed draft fields, not as the primary result format.
- Use `createLearningMaterialAnalysisModel` for the default provider-agnostic adapter. `createDeepSeekLearningMaterialAnalysisModel` is only a compatibility alias.

## Teacher Review Rules
- Before teacher confirmation, do not write to the student long-term profile, learning record, monthly report source pool, or confirmed feedback history.
- Before teacher confirmation, do not generate ready_to_send WeChat feedback.
- Only teacher-confirmed monthly snapshot copies can enter the monthly report source pool; unconfirmed AI analysis snapshots must be ignored by monthly report aggregation.
- The teacher must be able to inspect evidence, edit output, confirm selected profile updates, and see degrade/risk flags.
- WeChat feedback must be concise, warm, evidence-based, and free of absolute or anxiety-inducing claims.
- Forbidden feedback expressions include: 严重, 很差, 完全不会, 保证提分, 不认真, 基础很差, 一定能提高, 孩子不行, 家长必须.

## Definition Of Done
- Unsupported materials are blocked or routed to teacher review instead of analyzed as student ability.
- Explicit non-K12 and non-mainland-K12 scope signals are detected before model calls; university, adult, vocational, postgraduate, external language exam, professional qualification, Hong Kong/Macau/Taiwan exam-system, or international-curriculum materials cannot enter student ability analysis or claimable mainland K12 asset sets.
- VisionEvidencePacket is validated before text reasoning.
- External OCR/Layout/Vision adapter inputs are validated before packet generation; missing provider metadata, empty page/question arrays, duplicate IDs, mismatched nested question IDs, cross-question region/evidence attribution, invalid confidence, helper-template placeholders in ID/ref/path fields, invalid bbox/polygon geometry, or orphan page/region references must fail before any reasoning model call. When evaluation assets provide both `external_vision_input_path` and `vision_packet_path`, asset preflight must rebuild the adapter-derived packet and reject page/question/region/evidence/gate drift from the source Provider input.
- Real-sample case package readiness must validate `external_vision_input_path` when present; malformed Provider adapter input must return `fix_artifact_validation` before recommending VisionEvidencePacket generation or downstream labeling. If `vision_packet_path` is also present, readiness must rebuild the adapter-derived packet and reject page/question/region/evidence/gate drift from the source Provider input before downstream commands.
- VisionEvidencePacket validation rejects duplicate or orphan page/question/region/evidence refs, cross-question region/evidence attribution, gate evidenceRefs, and pipeline trace output_refs before any reasoning model call.
- VisionEvidencePacket pipeline trace records the selected OCR/Layout/Vision provider, open-source benchmark candidates, evidence source URLs, and license/deployment review notes; provider/model changes require rerunning the same evaluation assets.
- Provider trial reports must be generated and validated against the same VisionEvidencePacket before gold labeling or asset readiness review; their readiness, summary counts, blockers, warnings, next steps, provider candidates, and per-question segmentation/readiness fields must match the packet-derived report. They must not include raw OCR text, normalized text, or copied OCR/text content in any editable/report field.
- OCR/Vision provider changes must compare baseline and candidate provider trial reports on the same material before downstream reasoning/model regression; candidate reports must not regress page coverage, question coverage, total or per-question student-trace evidence, total or per-question answer-basis evidence, question order, same-question page/question-number identity, crop_ref coverage, segmentation status, per-question evidence readiness, or confidence.
- The reasoning model only consumes structured text evidence and emits parseable JSON.
- Every official conclusion has evidenceRefs and confidence/degrade metadata.
- Every analysis evidenceRef is validated against the same VisionEvidencePacket, allowed question-mapped side inputs, or monthly comparison previous-month refs; invented or cross-case refs must fail runner/asset preflight.
- Analysis question coverage is validated against the same VisionEvidencePacket; missing, extra, duplicate, or reordered `question_analyses` cannot become draft-ready or claimable assets.
- User-facing teacher reports, parent feedback, and monthly notes are assembled from the validated analysis JSON with source labels and internal source mapping.
- Material type, subject, stage, grade, and region/curriculum hints pass through the deterministic pre-classifier and are covered by regression tests before relying on model-specific reasoning, including common homework/practice/diagnostic wording and local textbook version labels. Multiple region or curriculum-version hits must be surfaced as review warnings and lower confidence instead of pretending a single source is certain.
