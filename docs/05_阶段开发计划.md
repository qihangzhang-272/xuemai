# Development Plan

本文件是阶段推进顺序的权威说明。每次进入新阶段前，先确认上一阶段已经验收，并更新 `开发日记/YYYY-MM-DD_开发日记.md`。

## Phase 0: 仓库与规则初始化

建立 `AGENTS.md`、`README.md`、环境变量模板和产品范围文档。

## Phase 1: UI 骨架与 Mock 页面

用 Next.js App Router、TypeScript、Tailwind CSS、lucide-react 和本地 shadcn/ui 风格组件，跑通老师端练习反馈核心页面。页面仍使用 mock data，不接 Supabase；已先提供独立服务端 AI 生成工具，后续再接入 UI。

验收重点：

- 所有核心路由可访问。
- 左侧导航可跳转。
- 学生列表可进入学生详情。
- 新建微信反馈页有练习材料表单和微信反馈预览。
- UI 保持 Apple / ChatGPT 极简风。
- `npm run lint`、`npm run typecheck`、`npm run build` 通过。

当前状态：已完成第一版 UI 骨架，后续如需调整 Phase 1，只做小范围体验修正。

## Phase 2: Supabase Auth + 数据库 Schema

接入 Supabase Auth、Postgres 表结构和 RLS。实现真实登录和老师数据隔离，暂不接 AI。

建议下一步先做本阶段，不同时接入 AI。

## Phase 3: 班级与学生 CRUD

实现班级、学生档案的创建、查看和编辑。

## Phase 4: 练习记录 + 微信反馈

保存练习记录，通过服务端 API route 调用 AI 生成单次微信反馈，并沉淀月度总结素材。

## Phase 5: 错题分析

录入错题，生成原因分析和举一反三训练建议。

## Phase 6: 月度总结

基于学生当月学习记录、微信反馈和错题记录生成月度总结。

## Phase 7: 学生洞察

根据学生长期练习记录形成简洁的学习洞察摘要。

## Phase 8: 部署与试用

部署到 Vercel，准备老师试用反馈。

## Mobile App Planning: 手机 App 后续规划

手机 App 暂不进入具体 UI 实现。等手机端 UI 设计完成后，再按 `docs/09_手机App开发规划.md` 推进移动端工程。

手机端第一版定位为老师课后快速处理工具，优先跑通：

- 登录。
- 选择学生。
- 拍照或上传练习材料。
- 补充老师备注。
- 生成微信反馈。
- 编辑并复制微信反馈。
- 保存记录到学生档案。

建议技术路线为 Expo React Native + TypeScript。开发机使用 Mac，优先用安卓手机真机测试，后续保留 iOS 发布能力。
