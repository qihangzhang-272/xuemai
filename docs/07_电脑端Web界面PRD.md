# 电脑端 Web 界面 PRD

> 历史页面 PRD：当前 PC Web 页面结构、聊天主入口、SkillCard 和分析详情页要求以 `docs/PRD.md` 为准。

## 1. 产品定位

电脑端 Web 是老师的主要 Agent 工作台，用于让老师把课后反馈、错题分析、学生档案整理、月度总结和家长沟通话术等教学后续任务交给学脉 AI 执行。设计重点不是“大后台”或功能集合，而是一个安静、清晰、可持续沉淀学生学习记录的 AI 助理工作台。

## 2. 目标用户

- 个体教培老师。
- 小型教培机构老师。
- 一对一和小班课老师。
- 需要批量处理多个学生练习反馈的老师。
- 需要在电脑上整理学生记录、查看月度总结和做课后服务复盘的老师。

## 3. 核心使用场景

- 老师课后坐在电脑前，直接用自然语言派发任务。
- 老师查看 AI 正在读取哪些学生和班级上下文，以及执行到哪一步。
- AI 缺少关键信息时，请老师中途确认。
- 老师审核 AI 产物，并保存到学生档案。
- 老师按班级查看哪些学生需要生成微信反馈。
- 老师进入某个学生档案，查看历史练习、微信反馈和月度总结素材。
- 老师录入本次练习材料、分数、表现和备注，生成可复制给家长的微信反馈。
- 老师月底查看某个学生的月度总结，并用于家长沟通或续费服务展示。

## 4. MVP 核心闭环

1. 老师进入电脑端 Agent 工作台。
2. 老师派发任务，例如“给周三数学提升班今天上课的学生生成家长反馈”。
3. AI 读取班级名单、学生档案、历史错题和上次反馈。
4. AI 展示执行步骤，并在缺少关键信息时等待老师确认。
5. AI 生成微信反馈、错题分析或月报等任务产物。
6. 老师审核、编辑、复制并保存。
7. 本次任务结果沉淀到学生档案。
8. 下一次任务继续调用历史档案。

## 5. 信息架构

电脑端 Web 主要导航：

- Agent 工作台：首页级入口，老师派任务、查看执行中任务、最近产物和当前上下文。
- 班级空间：展示班级和学生反馈状态，承接班级 Agent 的批量处理。
- 学生档案：查看某个学生的历史沉淀。
- 微信反馈生成：单次任务页面，只生成微信反馈。
- 月度总结：查看和生成月度总结。
- 设置：账号信息和 AI 输出偏好。

## 6. 页面清单

### 6.1 登录页

目标：让老师进入系统。

关键内容：

- 产品名称。
- 邮箱和密码输入框。
- 登录按钮。
- MVP 阶段可保留临时免登录说明。

设计要求：

- 居中单卡片布局。
- 不做营销落地页式复杂视觉。
- 文案简短、可信、安静。

### 6.2 Agent 工作台页

目标：让老师一进入系统就能把教学后续任务派给学脉 AI。

关键内容：

- 自然语言派任务入口。
- 六个快捷 Agent：反馈、错题、月报、档案、话术、班级。
- 正在执行任务：上下文、执行步骤、需要老师确认、结果预览。
- 最近产物：反馈、错题分析、月报等任务结果。
- 右侧上下文：当前班级、学生档案、常用语气和可调用档案。

设计要求：

- 第一屏要表达“老师是来派任务的”。
- 执行过程必须透明，不做黑箱生成。
- 结果必须能被审核、复制、编辑或保存到档案。
- Demo 阶段可以使用 mock 任务流，但文案必须体现长期档案沉淀。

### 6.3 班级空间页

目标：老师一眼看到当前班级学生反馈状态。

关键内容：

- 当前班级名称。
- 班级切换入口。
- 学生状态圆点阵。
- 重点关注学生区。
- 今日/本次任务完成度。
- 快捷入口：新建学生、生成反馈、查看月度总结。

学生状态：

- 红色：待生成微信反馈。
- 绿色：已生成微信反馈。
- 灰色空心：暂无本次练习记录。

设计要求：

- 学生圆点 44-52px，只放简称或头像缩写。
- 完整姓名和核心问题放在选中学生详情区，不塞进圆点。
- 班级页允许更强的全局概览感，但不要做数据大屏。

### 6.4 学生档案页

目标：承载一个学生的长期学习沉淀。

关键内容：

- 学生姓名、年级、科目、所在班级。
- 当前核心问题。
- 最近一次练习反馈。
- 微信反馈记录列表。
- 练习记录列表。
- 错题或薄弱点摘要。
- 月度总结入口。

设计要求：

- 学生信息优先，不要被统计卡片淹没。
- 历史记录按时间线或分组列表展示。
- AI 洞察只做辅助，不要喧宾夺主。

### 6.5 微信反馈生成页

目标：完成单次练习反馈生成。

电脑端推荐双栏：

- 左侧：录入区。
- 右侧：微信反馈预览区。

左侧字段：

- 学生。
- 练习类型：试卷、课堂练习、手改作业、作文、阅读题、口算题、其他。
- 练习标题。
- 分数或表现。
- 练习材料文本。
- 错题或问题描述。
- 老师备注。
- 后续安排。
- 反馈语气。

右侧内容：

- AI 微信反馈草稿。
- 编辑区。
- 复制到微信按钮。
- 保存到学生档案按钮。

设计要求：

- 单次页面只显性展示微信反馈，不展示长篇错因报告。
- AI 生成前展示空状态和示例结构。
- 生成中要有明确 loading 状态。
- 失败时说明原因，并允许重试。

### 6.6 月度总结页

目标：基于历史学习记录形成月度沟通材料。

关键内容：

- 学生和月份选择。
- 本月练习次数、反馈次数、主要问题。
- 月度总结草稿。
- 下月学习建议。
- 复制或导出入口。

设计要求：

- 月度总结和单次微信反馈要明显区分。
- 月度总结可以更正式，但仍保持老师可编辑。

### 6.7 设置页

目标：配置老师信息和 AI 输出偏好。

关键内容：

- 老师姓名。
- 机构名称。
- 常用反馈语气。
- 微信反馈长度偏好。
- 常用结束语。

## 7. 电脑端布局规范

- 推荐画布宽度：1440px / 1600px。
- 左侧导航固定，宽度 220-260px。
- 主内容最大宽度 1100-1280px。
- 一级页面使用宽松布局。
- 表单页可用左右双栏。
- 二级页面需要返回按钮。
- 班级选择只在班级页出现，不全局滥用。

## 8. 视觉规范

- 风格：Apple / ChatGPT 极简风。
- 背景：白色或浅灰。
- 文字：黑色、深灰、中灰三级。
- 强调色：少量蓝色。
- 状态色：低饱和红、绿、灰。
- 圆角：8-16px，根据模块层级使用。
- 阴影：轻柔，不做厚重卡片。
- 图标：少量使用 lucide 风格线性图标。

## 9. 关键状态设计

- 空状态：无班级、无学生、无练习记录、无月度总结。
- 加载状态：生成反馈中、保存中。
- 错误状态：AI 生成失败、保存失败、网络异常。
- 成功状态：已复制、已保存。
- 未配置状态：未配置 AI Key 或 Supabase 时的提示。

## 10. 设计交付物

建议设计师输出：

- 电脑端 Web 全局布局。
- Agent 工作台页。
- 班级空间页。
- 学生档案页。
- 微信反馈生成页。
- 月度总结页。
- 设置页。
- 基础组件规范：按钮、输入框、文本域、状态标签、学生圆点、折叠区、反馈预览卡。

## 11. 验收标准

- 老师能在 10 秒内理解当前班级哪些学生需要处理。
- 老师能从班级页进入学生档案，再进入反馈生成页。
- 反馈生成页明确表达“左侧录入，右侧微信反馈预览”。
- 单次任务不误导老师以为会生成正式报告。
- 视觉不呈现传统企业后台、飞书后台或复杂数据大屏感。
