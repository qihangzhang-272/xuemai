# 学脉理想版产品需求文档（产品愿景 PRD）

> 本文档描述学脉在理想状态下的完整产品形态，聚焦客户、价值、页面、流程、功能、版本和商业边界。当前产品执行仍以 docs/PRD.md 为准。

## 一、产品愿景

### 1. 文档信息

| 版本 | 日期 | 作者 | 状态 |
|---|---|---|---|
| Vision V3.2.0 | 2026-08-06 | 用户 | 本体重组后的理想产品蓝图 |

### 2. 一句话定位

学脉是面向中国小学到高中学科类独立老师与教培机构的 AI 教学服务操作系统。

它以学生为统一主线，把家长咨询、新生测评、报名、课程、课堂、学生材料、专业分析、微信沟通、成长档案、阶段报告、服务跟进和续费准备连接起来。

### 3. 理想产品体验

对老师：

- 老师仍按熟悉的方式说话、拍照、上传和微信沟通。
- 学脉自动整理成可检查的教学服务记录。
- 同一内容不需要反复填写。
- AI 帮助整理、分析和表达，但老师保留最终判断。

对家长：

- 在微信中持续收到有依据、看得懂的反馈。
- 可以看到孩子一段时间内真实发生的变化。
- 重要问题有人负责、有人回复、有人继续跟进。

对机构：

- 招生、教学和家长服务围绕同一学生连续展开。
- 负责人看到服务是否完成、哪里出现问题、谁在处理。
- 不靠增加老师表格和日报获得管理信息。
- 续费沟通建立在真实服务价值上，而不是营销话术上。

### 4. 北极星闭环

家长咨询
→ 新生测评
→ 报名成为正式学生
→ 课程与课堂服务
→ 学生材料与专业分析
→ 家长微信反馈
→ 老师确认学生档案
→ 阶段报告与成长记录
→ 家长问题与服务跟进
→ 下一阶段教学与续费准备

这条链路只有一位学生、一个连续身份和一套可信记录。

### 5. 北极星指标

每周每位活跃老师完成的“可信教学服务闭环”数量。

一次闭环至少包含：

- 一条真实课堂或学生材料来源。
- 一份老师可检查的结果。
- 一次明确的反馈或入档动作。
- 一个可在未来继续使用的学生记录。

## 二、客户与版本

### 1. 产品版本

理想状态仍然只做两个版本：

| 版本 | 客户 | 产品价值 |
|---|---|---|
| 个人版 | 独立老师、个人名师、单账号工作室 | 把一个人的教学服务变得持续、专业、可复用 |
| 机构版 | 多账号、多角色共同服务学生的机构 | 把多人的服务连接起来，形成一致、可交接、可查看的服务体系 |

不设置：

- 工作室版。
- 团队版。
- 企业版。
- 集团版。

归类原则：

- 一个人使用就是个人版。
- 两人及以上需要独立账号和协作就是机构版。
- 版本由协作关系决定，不由机构名称和规模决定。

### 2. 核心角色

| 角色 | 最重要的工作 | 学脉提供的价值 |
|---|---|---|
| 独立老师 | 教学、反馈、招生和家长服务都由自己完成 | 一个人也能形成完整专业服务 |
| 授课老师 | 上好课并记录真实学生表现 | 少整理，记录直接变成反馈与档案 |
| 助教 | 收集材料、补充记录、跟进练习 | 与老师共享同一学生上下文 |
| 班主任 | 维护家长关系和服务进度 | 看得见课堂事实，回复不靠猜 |
| 课程顾问 | 处理咨询、试听、测评和续费沟通 | 从招生到教学使用同一学生记录 |
| 教务 | 安排服务关系和处理交接 | 清楚谁负责什么、哪里被遗漏 |
| 教研负责人 | 统一专业标准和改进服务质量 | 看方法和结果，不只检查文案格式 |
| 机构负责人 | 关注服务质量、客户关系和经营结果 | 从真实服务中看风险和价值 |
| 家长 | 了解孩子情况、表达问题、获得回应 | 反馈连续、有依据、有人负责 |
| 学生 | 被持续了解和支持 | 不被单次成绩或标签定义 |

### 3. 客户分层

| 客户阶段 | 主要问题 | 首要产品能力 |
|---|---|---|
| 起步独立老师 | 学生不多，但所有事情都靠自己 | 聊天工作台、反馈、档案、微信沟通 |
| 成熟个人老师 | 学生多、家长沟通多、需要月度服务 | 待处理、月报、班级服务、个人经营提醒 |
| 小型机构 | 多人协作但流程靠微信群和表格 | 角色、分配、交接、服务状态 |
| 中型机构 | 招生、教学、家长服务彼此割裂 | 新生到在读连续记录、机构范围工作台 |

理想状态也不进入集团总部和多区域治理。

## 三、产品原则

1. 学生是唯一主线，不按部门重复建档。
2. 聊天是老师入口，不把老师拖进复杂后台。
3. 同一事实只记录一次，后续结果从它继续生长。
4. AI 负责整理和辅助判断，老师负责最终结果。
5. 没有真实学生痕迹，不判断学生能力。
6. 单次材料不生成长期负面标签。
7. 家长情绪是一次沟通事件，不是永久人格。
8. 家长微信消息可以直接进入学脉，但最终回复由老师确认。
9. 反馈状态优先于入档状态，因为老师首先关心是否已经服务家长。
10. 个人版保持极简，机构版增加协作但不改变老师的核心使用方式。
11. 管理来自真实服务过程，不来自额外填报。
12. 续费信号来自服务完成和家长沟通，不来自虚构概率。
13. 产品只掌握与学生服务连续性有关的核心内容。
14. 完整财务、人事、工资、库存和集团管理不是学脉的产品方向。
15. 总览必须帮助用户发现问题并进入处理，不做只展示数字的装饰性大屏。
16. 批量操作用于减少重复劳动，但不能取消逐学生结果、检查状态和责任人。

## 四、完整产品结构

### 1. 个人版与机构版共用产品骨架

| 一级入口 | 页面定位 | 核心内容 |
|---|---|---|
| 工作台 | 查看整体状态和未完成责任 | 日程、异常、待反馈、待回复、待跟进、服务提醒 |
| 会话 | 日常记录和沟通 | 学生会话、班级会话、家长消息、结果卡片 |
| 学生 | 查看持续学生主体的关系和历史 | 生命周期筛选、详情、服务周期、时间线、报告 |
| 班级 | 查看群体教学关系和个体差异 | 班级、课程事实、成员、公共记录、逐学生反馈 |
| 管理 | 管理低频配置和规模化动作 | 偏好、成员、角色、分配、交接、批量操作、数据来源 |

产品组合规则：

- 个人版与机构版使用相同的五个一级入口，不让老师切换到另一套后台逻辑。
- 机构版在工作台增加团队和机构范围，在管理页增加成员、权限、分配、交接、质量规则和数据来源。
- 新生、测评、报名、续费和结束属于同一学生的生命周期阶段，不单独建立招生系统。
- 服务中心并入工作台和会话结果卡片，不再建立独立结果孤岛。
- 批量管理是对象列表与管理页中的多选操作模式，不作为一级业务世界。

### 2. 机构版扩展

| 扩展位置 | 机构版增加的能力 |
|---|---|
| 工作台 | 机构范围、团队范围、逾期、无人负责、高优先级问题、待交接 |
| 会话 | 按负责范围查看学生、班级和家长消息，显示实际处理人 |
| 学生 | 多角色服务关系、负责人变化、机构服务历史 |
| 班级 | 授课老师、助教、班主任、成员反馈完成情况 |
| 管理 | 成员、角色、权限、分配、交接、模板、批量操作和数据来源 |

### 3. 家长端

家长主要在微信中完成服务，不要求下载独立应用。

| 页面或入口 | 主要内容 |
|---|---|
| 微信对话 | 接收老师反馈、表达问题、获得回复 |
| 学习记录页 | 查看老师已经发布的课堂和材料反馈 |
| 报告页 | 查看月报、阶段报告和成长变化 |
| 服务确认页 | 确认重要事项、授权和资料 |
| 沟通页 | 围绕具体反馈继续追问 |

家长看不到：

- AI 草稿。
- 老师内部备注。
- 未确认的学生判断。
- 机构内部检查信息。
- 其他学生和家长内容。

### 4. 移动端

移动端围绕“下课后三分钟”和“家长消息及时处理”设计：

- 快速选择学生。
- 语音或文字记录课堂。
- 拍照上传学生材料。
- 查看结果卡片。
- 编辑并回复家长。
- 完成待跟进。
- 查看学生近期状态。

移动端不承载复杂机构管理。

## 五、理想全流程

### 1. 招生与新生测评

家长咨询进入学脉
→ 创建家长和意向学生关系
→ 记录年级、学科和需求
→ 安排试听或新生测评
→ 上传学生真实材料
→ 生成测评分析与家长反馈
→ 记录家长问题和下一步
→ 报名后直接转为正式学生

产品结果：

- 招生承诺有记录。
- 测评依据可回看。
- 报名后不重新建档。
- 授课老师能看到前期真实信息。

### 2. 课程与课堂服务

创建课程关系
→ 安排班级或一对一课程
→ 老师上课
→ 记录课堂和学生表现
→ 生成课堂反馈
→ 课次完成
→ 学生时间线更新

课程只提供与教学服务连续性有关的能力，不扩张为复杂排课系统。

### 3. 学生学习材料

上传作业、试卷、错题、笔记或练习
→ 判断是否包含学生学习痕迹
→ 生成专业分析
→ 老师检查
→ 形成家长反馈和入档候选
→ 后续材料继续验证变化

长期价值：

- 单次材料形成一次可信记录。
- 多次记录形成变化趋势。
- 趋势可以进入月报和阶段报告。
- 所有长期结论都能回到真实来源。

### 4. 微信家长服务

家长微信消息进入学脉
→ 归到对应学生和服务关系
→ AI 整理沟通重点
→ 区分已知事实、待核实内容和建议回复
→ 老师或班主任补充事实
→ 检查并回复
→ 记录结果和后续动作

理想体验：

- 老师不复制家长原话到多个工具。
- 家长不需要改变微信使用习惯。
- 班主任能看到授课老师已经确认的课堂事实。
- 高优先级问题不会因为人员忙碌而丢失。
- 沟通完成后，学生服务记录自动连续。

### 5. 学生档案与成长报告

课堂、材料、反馈和沟通产生候选内容
→ 老师确认值得长期保留的事实
→ 进入学生时间线
→ 形成阶段变化
→ 生成月报、阶段报告和成长报告

学生档案不等于静态标签，而是：

- 学过什么。
- 做过什么。
- 在什么情况下表现如何。
- 哪些问题重复出现。
- 哪些方向已经改善。
- 老师做过哪些服务。
- 家长关注过哪些问题。

### 6. 服务跟进与续费准备

系统根据真实服务过程提示：

- 长时间没有课堂反馈。
- 家长问题尚未回复。
- 高优先级沟通尚未完成。
- 阶段报告应该准备。
- 服务周期即将结束。
- 续费前缺少完整阶段总结。

系统不做：

- 判定家长一定续费。
- 给出确定性流失概率。
- 自动发送营销话术。
- 用教学评价给销售施压。

理想续费准备：

服务记录完整
→ 阶段报告清楚
→ 家长问题已处理
→ 老师给出下一阶段建议
→ 课程顾问基于真实服务沟通

### 7. 机构协作

学生进入机构
→ 明确授课老师、助教、班主任和课程顾问
→ 每个角色在同一学生主线上工作
→ 待处理事项明确到人
→ 服务结果完成后同步更新
→ 负责人只查看异常和结果
→ 人员变动时完成交接

管理重点：

- 是否完成。
- 是否及时。
- 是否有依据。
- 家长是否得到回应。
- 是否还有未解决事项。

不是：

- 监控老师每一句话。
- 让老师填写更多日报。
- 用统一话术替代老师专业判断。

### 8. 工作台与批量操作

个人老师进入工作台
→ 查看学生、班级、课程、反馈、家长消息和月报的整体状态
→ 优先看到待处理与异常
→ 点击任一数字进入对应学生或清单

机构负责人进入机构范围工作台
→ 查看教学服务、家长服务、新生服务和成员协作状态
→ 发现逾期、无人负责或高优先级问题
→ 进入清单并分配处理

需要重复处理时：

选择学生、班级或事项
→ 选择批量动作
→ 查看影响范围和跳过规则
→ 确认
→ 查看整体结果和逐项明细

理想批量能力包括：

- 批量创建或导入学生基本资料。
- 批量加入班级、调整班级和服务状态。
- 批量分配授课老师、班主任和课程顾问。
- 批量生成逐学生反馈草稿、月报草稿和阶段报告草稿。
- 批量安排普通跟进事项、调整负责人和完成时间。
- 批量交接学生、班级和未完成事项。
- 批量归档已经结束且没有待处理事项的学生。

批量边界：

- 个性化结果始终按学生独立保存。
- 批量生成不等于批量确认。
- 未经逐项检查的个性化反馈不能直接批量发送。
- 学生长期档案不能一键批量确认。
- 投诉、退费和安全类事项不能普通批量关闭。
- 总览中的每个数字都必须能进入具体对象和处理页面。

## 七、关键页面定义

### 1. 工作台

目标：老师打开后立刻了解个人教学服务的整体状态，并知道今天最需要处理什么。

内容：

- 今日课程。
- 待反馈。
- 家长新消息。
- 待核实。
- 待跟进。
- 即将到期的阶段报告。
- 快速记录入口。
- 服务中学生和班级。
- 本月反馈与月报完成情况。
- 长时间没有新记录的学生。
- 最近一段时间的服务变化。

不出现：

- 复杂图表。
- 大量经营数字。
- 与老师无关的机构信息。

### 2. 会话页

目标：完成日常记录、分析和沟通。

内容：

- 学生、班级和家长会话。
- 课堂记录。
- 材料上传。
- 微信消息。
- 结果卡片。
- 反馈和入档操作。

会话页不展开完整长报告。

### 3. 学生详情页

目标：一分钟了解学生最近情况。

内容：

- 基础信息和服务关系。
- 当前状态。
- 近期关注。
- 最近课堂。
- 最近材料分析。
- 最近家长沟通。
- 待反馈和待跟进。
- 时间线和报告。

学生详情页以看为主，不做成操作工作台。

### 4. 分析详情页

目标：老师完整检查一次学生材料分析。

内容：

- 本次材料和范围。
- 结论概览。
- 可以确认的表现。
- 错误或问题模式。
- 相关知识点。
- 学习方法表现。
- 重点错题或重点内容。
- 近期巩固方向。
- 家长反馈草稿。
- 来源和注意事项。

不出现：

- 每日打卡。
- 学生任务派发。
- 自动教案。
- 保证提分。

### 5. 学生生命周期视图

目标：用同一学生主体承载咨询、测评、试听、正式服务、暂停、续费和结束，不因阶段变化重新建档。

内容：

- 新咨询。
- 待测评。
- 待反馈。
- 服务中、暂停和即将结束。
- 家长沟通和待跟进。
- 已报名和未报名记录。

### 6. 机构范围工作台

目标：负责人只看需要关注的服务状态。

内容：

- 今日未完成反馈。
- 家长问题未回复。
- 高优先级事项。
- 逾期跟进。
- 学生无人负责。
- 即将交接。
- 阶段报告完成情况。

不以老师聊天数量、在线时长等指标评价教学质量。

### 7. 批量操作模式

目标：让个人老师和机构成员在学生、班级、工作台清单和管理页中一次处理多个同类对象，同时保留逐项结果。

操作结构：

- 顶部：对象类型、班级、负责人、状态和时间筛选。
- 中部：可多选的学生、班级或事项列表。
- 底部或侧栏：当前可执行的批量动作。
- 执行前：影响数量、变化内容、跳过条件。
- 执行后：成功、失败、跳过和逐项结果。

核心批量动作：

- 分班和调整班级。
- 分配或更换负责人。
- 调整服务状态。
- 生成反馈、月报和报告草稿。
- 创建或调整普通跟进事项。
- 学生和服务交接。
- 符合条件的归档。

页面规则：

- 不同对象只显示适用的批量动作。
- 个性化结果保持逐学生独立。
- 有风险或未完成事项时明确跳过。
- 普通成员只能操作自己负责范围。
- 任何批量结果都可展开查看单项明细。

## 八、统一产品状态

### 1. 教学结果状态

| 状态 | 含义 |
|---|---|
| 待反馈 | 有反馈草稿，尚未完成家长反馈 |
| 已反馈 | 老师已完成反馈 |
| 待入档 | 有内容可进入学生档案 |
| 已入档 | 老师已确认进入档案 |

反馈状态优先展示，入档状态作为补充。

### 2. 家长沟通状态

| 状态 | 含义 |
|---|---|
| 待认领 | 尚未确认对应学生和家长 |
| 待核实 | 缺少课堂或服务事实 |
| 待回复 | 已有可处理内容 |
| 已回复 | 本次回复完成 |
| 待跟进 | 仍有后续事项 |
| 已完成 | 本次沟通结束 |
| 已放弃 | 明确不再继续处理 |

### 3. 新生状态

| 状态 | 含义 |
|---|---|
| 新咨询 | 刚进入服务范围 |
| 待试听 | 尚未完成试听 |
| 待测评 | 尚未完成测评 |
| 待反馈 | 已测评，尚未反馈 |
| 待决定 | 家长尚未确认 |
| 已报名 | 转为正式学生 |
| 未报名 | 保留历史但不继续服务 |
| 已归档 | 不再主动跟进 |

### 4. 服务周期状态

| 状态 | 含义 |
|---|---|
| 待开始 | 已建立服务关系 |
| 服务中 | 正常上课和反馈 |
| 暂停 | 暂时停止服务 |
| 即将结束 | 需要阶段总结和后续沟通 |
| 已续费 | 进入下一服务周期 |
| 已结束 | 当前服务完成 |

教学评价和经营结果必须分开。

### 5. 批量处理状态

| 状态 | 含义 |
|---|---|
| 未选择 | 尚未选择对象 |
| 已选择 | 已选择对象，可选择批量动作 |
| 待确认 | 正在查看影响范围和跳过规则 |
| 处理中 | 批量操作正在进行 |
| 全部完成 | 所有符合条件的项目完成 |
| 部分完成 | 部分成功，部分失败或跳过 |
| 已取消 | 未执行或停止剩余项目 |

## 九、商业模式

### 1. 个人版

收费逻辑：

- 按月或按年订阅。
- 包含基础学生数量和常用教学服务。
- 超出部分按学生规模或使用量升级。

核心权益：

- 学生与班级。
- 课堂记录。
- 学生材料分析。
- 微信反馈与家长沟通。
- 学生档案。
- 月报。
- 移动端。
- 个人工作台和常用批量操作。

### 2. 机构版

收费逻辑：

- 机构基础订阅。
- 按活跃成员和学生规模分档。
- 高级服务管理能力作为更高档位。

核心权益：

- 个人版全部能力。
- 多账号和角色。
- 学生分配和交接。
- 招生与新生测评。
- 家长服务工作台。
- 机构模板和服务检查。
- 机构范围工作台和经营摘要。
- 机构批量操作和批量交接。

### 3. 试用

- 试用是订阅状态，不是第三个版本。
- 个人版试用完整个人闭环。
- 机构版试用必须邀请至少两位不同角色成员。
- 试用成功标准不是“生成过一次 AI 文案”，而是完成一次真实服务闭环。

## 十一、阶段路线

### 阶段 A：个人版可信闭环

- 聊天工作台。
- 课堂记录。
- 学生材料分析。
- 微信反馈。
- 确认入档。
- 学生详情。

验证：独立老师是否愿意持续使用。

### 阶段 B：微信家长服务

- 家长消息进入学脉。
- 消息认领。
- 回复建议。
- 老师确认回复。
- 待跟进。
- 历史沟通。

验证：是否显著减少跨工具搬运和漏回复。

### 阶段 C：连续教学服务

- 月报。
- 阶段报告。
- 班级服务。
- 课程与课次。
- 移动端。
- 家长查看页面。
- 个人工作台。
- 反馈和月报草稿的批量生成与检查队列。

验证：是否从单次 AI 使用变成持续服务习惯。

### 阶段 D：机构版

- 成员与角色。
- 学生分配。
- 服务负责人。
- 机构待处理。
- 模板与服务检查。
- 交接。
- 机构范围工作台。
- 学生、班级、负责人、报告和跟进的批量操作。

验证：机构协作是否减少重复沟通，而不是增加管理负担。

### 阶段 E：招生到续费连续主线

- 新生咨询。
- 试听和测评。
- 正式学生转换。
- 服务周期。
- 阶段总结。
- 续费准备。

验证：招生、教学和家长服务能否围绕同一学生连续运转。

### 阶段 F：规模化

- 更多学科和地区。
- 更成熟的个人版和机构版套餐。
- 老师方法沉淀。
- 机构最佳实践。
- 更完整的微信家长服务。

目标：形成稳定、可信、可持续的教培服务产品。

## 十二、理想终局验收

### 1. 对老师

- 老师可在一次聊天中完成记录、分析、反馈和入档。
- 家长微信消息直接进入对应学生上下文。
- 老师不需要重复输入同一课堂事实。
- 个人版在功能完整的同时保持简单。
- 老师可通过总览发现异常，并直接进入具体学生或事项处理。
- 学生较多时可使用对象列表的批量模式减少重复操作。

### 2. 对家长

- 家长不需要改变微信使用习惯。
- 看到的内容都是老师已经确认的正式版本。
- 重要问题能找到明确处理人和结果。
- 报告能说明依据和变化，不使用空泛套话。

### 3. 对学生

- 长期记录来自真实课堂和材料。
- 单次成绩不形成永久标签。
- 历史更正和变化得到保留。
- 学生不会因为家长情绪被贴标签。

### 4. 对机构

- 招生、教学和家长服务使用同一学生记录。
- 负责人能看到异常、责任人和处理结果。
- 机构范围工作台覆盖教学、家长、新生和成员协作状态。
- 批量操作支持筛选、选择、影响确认和逐项结果明细。
- 个性化反馈即使批量生成，也必须按学生独立检查。
- 老师离开时可以完成清晰交接。
- 管理视图不依赖老师额外填写日报。
- 产品只有个人版和机构版。

### 5. 产品边界

- 不做集团版。
- 不做完整财务、人事、工资和库存。
- 不做自动营销平台。
- 不让 AI 未经老师确认回复家长。
- 不自动给学生或家长贴长期标签。
- 不保证提分、报名和续费。
- 不以功能数量作为产品价值。

## 十三、理想产品结论

理想状态下，学脉不是一套“什么都有”的教培后台，而是教培服务真正发生的地方。

它连接的是：

- 老师真实做过的教学。
- 学生真实留下的学习痕迹。
- 家长真实提出的问题。
- 机构真实完成的服务。
- 下一阶段真实需要做的事情。

产品最终形成四个长期价值：

1. 老师拥有可积累的专业服务能力。
2. 学生拥有连续、可信、不过度标签化的成长记录。
3. 家长持续看见有依据的服务价值。
4. 机构在不增加老师负担的情况下形成可协作、可交接、可改进的服务体系。

这就是学脉的理想产品形态。
