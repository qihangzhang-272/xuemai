# AI 练习反馈手机 App Stitch PRD

## 1. 给 Stitch 的生成目标

请生成一个面向教培老师的手机 App UI。这个 App 帮助老师在课后快速处理学生练习材料，生成可以直接复制到微信发送给家长的反馈，并将记录沉淀到学生档案，用于月底生成月度总结。

本次只设计手机 App，不设计电脑端 Web、不设计学生端、不设计家长端、不设计微信小程序。

产品关键词：

- AI 练习反馈
- 拍照/上传练习材料
- 生成微信家长反馈
- 学生档案沉淀
- 月度总结素材
- 老师移动端高频工具

## 2. 产品定位

这是一个给教培老师使用的移动端 AI 反馈助手。

老师常见场景：

- 刚下课，需要马上给家长发微信反馈。
- 手上有学生试卷、作文、口算题、阅读题、课堂练习或老师手改作业。
- 老师希望拍照或简单录入后，AI 帮忙整理成自然、专业、温和的微信反馈。
- 老师不希望手机端出现复杂后台、数据大屏或长篇分析。

核心承诺：

老师用手机完成“选学生 -> 加材料 -> 生成微信反馈 -> 复制发送”。

## 3. MVP 核心流程

1. 老师打开 App。
2. 进入今日待处理页。
3. 选择学生，或直接点击快速生成。
4. 拍照、上传或粘贴练习材料。
5. 补充分数、表现、错题、老师备注和后续安排。
6. 点击生成微信反馈。
7. 查看并轻度编辑微信反馈草稿。
8. 一键复制到微信。
9. 保存记录到学生档案。
10. 月底基于历史记录生成月度总结。

单次任务只突出“微信反馈”。不要在单次任务界面展示复杂错因报告、长篇分析报告或数据看板。

## 4. 目标用户

- 个体教培老师。
- 一对一老师。
- 小班课老师。
- 经常用微信向家长反馈学习情况的老师。
- 经常需要处理学生练习、作文、试卷和作业反馈的老师。
- 希望用月度总结辅助续费沟通和服务展示的老师。

## 5. 手机 App 信息架构

底部 Tab 使用 4 个：

1. 今日
2. 学生
3. 生成
4. 我的

不要把“月度总结”放成底部一级 Tab。月度总结放在学生详情中，作为沉淀结果入口。

不要做复杂班级大屏。班级只作为筛选条件或学生分组出现。

## 6. 页面清单

### 6.1 启动/登录页

目标：让老师快速进入产品。

内容：

- 产品名：AI 练习反馈
- 副标题：拍照录入练习，一键生成微信反馈
- 手机号或邮箱登录入口
- 演示体验入口

设计要求：

- 轻量、温暖、有亲和力。
- 一个主按钮即可，不要多个按钮争抢注意力。
- 不做营销落地页。

### 6.2 今日页

目标：让老师知道今天最该处理什么。

内容：

- 今日待生成反馈数量。
- 最近处理的班级或学生。
- 待处理学生列表。
- 快速生成按钮。

列表项字段：

- 学生姓名
- 班级/科目
- 当前状态：待生成反馈、已生成反馈、暂无材料
- 最近材料类型：试卷、作文、作业、阅读、口算等

主操作：

- 点击学生进入学生详情。
- 点击快速生成进入生成流程。

设计要求：

- 列表优先。
- 待处理事项放在最上面。
- 不做密集表格。
- 不使用大量彩色卡片。

### 6.3 学生列表页

目标：快速找到学生。

内容：

- 搜索框。
- 班级筛选。
- 科目筛选。
- 学生列表。
- 新建学生入口。

学生列表项：

- 学生姓名
- 年级/科目
- 最近状态
- 最近反馈日期

设计要求：

- 搜索框放顶部。
- 筛选使用轻量胶囊按钮。
- 不要大面积使用彩色标签。

### 6.4 学生详情页

目标：查看学生最近沉淀，并从这里发起新反馈。

内容：

- 学生姓名、年级、科目。
- 当前核心问题。
- 最近微信反馈。
- 最近练习记录。
- 月度总结入口。
- 新建微信反馈按钮。

主操作：

- 新建微信反馈。
- 查看最近反馈。
- 查看月度总结。

设计要求：

- 顶部学生信息简洁清楚。
- “新建微信反馈”是主要按钮。
- 历史记录使用时间线或清爽列表。
- 不要把月度总结做成首页主功能。

### 6.5 快速生成页

目标：完成单次微信反馈生成。

建议使用分步流程：

1. 选择学生
2. 添加材料
3. 补充表现
4. 生成反馈

输入方式：

- 拍照
- 相册上传
- 粘贴文本
- 手动输入

字段：

- 学生
- 练习类型
- 分数或表现
- 练习材料
- 错题或问题
- 老师备注
- 后续安排
- 反馈语气

设计要求：

- 手机端不要把所有字段塞在一个长表单中。
- 使用分步卡片或分组折叠。
- 底部固定主按钮。
- 当前步骤必须清楚。
- 生成中要显示明确 loading 状态。

### 6.6 微信反馈预览页

目标：让老师确认、编辑并复制微信反馈。

内容：

- 微信反馈草稿。
- 编辑入口。
- 复制到微信按钮。
- 保存记录按钮。
- 重新生成按钮。

设计要求：

- 微信反馈文本是页面视觉中心。
- 复制按钮必须最醒目。
- 复制成功后提示：已复制，可粘贴到微信。
- 重新生成是次要按钮，不要和复制按钮同等抢眼。
- 不展示复杂 AI 分析报告。

### 6.7 我的页

目标：管理账号和 AI 输出偏好。

内容：

- 老师姓名。
- 机构名称。
- 默认反馈语气。
- 默认反馈长度。
- 常用结束语。
- 退出登录。

设计要求：

- 设置项用简单列表。
- 危险操作如退出登录使用低频样式，不要放在页面顶部。

## 7. 视觉风格

整体风格参考 Duolingo 的亲和力和游戏化轻快感，但不要复制 Duolingo 的品牌形象、吉祥物、插画或具体视觉资产。

应该像：

- 友好
- 轻快
- 圆润
- 有一点学习激励感
- 手机端触感明确
- 老师愿意每天打开的小工具

不要像：

- 飞书后台
- 企业 CRM
- 维基百科页面
- 数据大屏
- 传统教务系统
- 复杂 LMS

## 8. 色彩原则

请严格控制颜色数量。不要让每个卡片都有不同颜色。

推荐配色结构：

- 60%：中性浅背景，如暖白、浅灰、淡米白。
- 30%：柔和品牌绿或浅绿色，用于学习感、完成感和主视觉氛围。
- 10%：强调色，用于主按钮、关键状态或生成成功反馈。

建议色板：

- 背景：`#F7F8F3`
- 前景卡片：`#FFFFFF`
- 主文字：`#1F2933`
- 次要文字：`#6B7280`
- 边框：`#E5E7EB`
- 主绿色：`#58CC02`
- 深绿色：`#3FA000`
- 浅绿色背景：`#EAF8DD`
- 强调蓝：`#1CB0F6`
- 警示红：`#FF4B4B`
- 金币黄：`#FFC800`

使用规则：

- 背景不要使用亮色。
- 大面积区域优先使用中性色。
- 图标多数情况下不要上色，只在状态或主操作中使用颜色。
- 状态色只用于表达状态：成功、待处理、错误、警示。
- 浅色背景上优先使用深色文字，不要用低对比白字。
- 所有按钮和文字需要满足基本可读性，避免低对比度。
- 不要使用五种以上强调色互相争抢注意力。

## 9. 组件风格

### 9.1 底部 Tab

- 4 个 Tab：今日、学生、生成、我的。
- 当前 Tab 使用主绿色。
- 未选中 Tab 使用中性灰。
- 图标简洁，不要过度彩色。

### 9.2 主按钮

- 高度：48-56px。
- 圆角：14-18px。
- 使用主绿色。
- 按下态使用稍深绿色。
- 禁用态使用低饱和灰绿或浅灰。

### 9.3 卡片

- 圆角：16-20px。
- 背景白色或非常浅的绿色。
- 使用轻微阴影或简单边框，不要两者都很重。
- 卡片数量要少。

### 9.4 学生状态

状态：

- 待生成反馈：使用温和橙/红色小点。
- 已生成反馈：使用绿色小点。
- 暂无材料：使用灰色小点或空心圆。

不要把整张学生卡片染成状态色。

### 9.5 上传组件

- 拍照入口要明显。
- 可用大号圆角上传区域。
- 图标可以使用相机或图片符号。
- 上传区域不要使用强烈彩色背景。

### 9.6 微信反馈文本框

- 背景使用白色或浅绿色。
- 文本区域要适合阅读。
- 复制按钮固定在底部或文本卡片下方。

## 10. 移动端交互

- 所有主要按钮适合拇指点击。
- 主要操作尽量放在底部固定区域。
- 表单分步，避免长页面疲劳。
- 生成过程中不要丢失输入内容。
- 网络失败时保留用户已输入内容。
- 返回时如果有未保存内容，需要提示确认。
- 复制成功要有明确反馈。
- 长文本编辑不应误触清空。

## 11. 状态设计

Stitch 需要生成以下状态或在设计中预留：

- 空状态：今天暂无待处理反馈。
- 加载状态：微信反馈生成中。
- 成功状态：微信反馈已生成。
- 复制成功：已复制，可粘贴到微信。
- 错误状态：生成失败，请稍后重试。
- 未选择学生。
- 未上传材料。
- 保存成功。

## 12. Stitch 生成要求

请生成高保真手机 App UI，尺寸优先使用 iPhone 15 或 390 x 844。

需要输出这些核心屏幕：

1. 登录页
2. 今日页
3. 学生列表页
4. 学生详情页
5. 快速生成 - 选择学生
6. 快速生成 - 添加材料
7. 快速生成 - 补充表现
8. 微信反馈预览页
9. 我的页

不要生成：

- 电脑端 Web 页面
- 数据大屏
- 管理后台表格
- 学生端
- 家长端
- 支付页面
- 复杂排课页面

## 13. Stitch Prompt 可直接使用版本

请设计一个手机 App，产品名为「AI 练习反馈」。这是给教培老师使用的移动端 AI 工具，帮助老师拍照或上传学生练习材料，补充分数、错题和老师备注，然后生成可以直接复制到微信发给家长的反馈。单次任务只突出微信反馈，不展示复杂 AI 分析报告。系统后台会沉淀记录，用于月底生成月度总结。

设计风格参考 Duolingo 的友好、圆润、轻快和学习激励感，但不要复制 Duolingo 的品牌、吉祥物或插画。整体要现代、简约、适合老师高频使用。避免飞书式后台、企业 CRM、维基百科式纯文本页面和默认蓝色链接。

请使用 60-30-10 色彩原则：60% 中性浅背景，30% 柔和绿色学习氛围，10% 强调色。背景使用暖白或浅灰，卡片用白色，主按钮用绿色，状态色只用于待处理、已完成、错误和提醒。不要让每个卡片都有不同颜色。大多数图标保持灰色，只有当前 Tab、主按钮和状态提示使用颜色。所有文字需要高可读性，浅色背景上使用深色文字。

底部 Tab 包含「今日」「学生」「生成」「我的」。核心流程是：今日待处理 -> 选择学生 -> 拍照/上传/粘贴材料 -> 补充分数和问题 -> 生成微信反馈 -> 编辑并复制 -> 保存到学生档案。请生成登录页、今日页、学生列表页、学生详情页、快速生成分步页、微信反馈预览页和我的页。

交互上，主要按钮放在底部，按钮高度至少 48px，适合拇指点击。表单使用分步流程，避免长表单。微信反馈预览页必须突出反馈文本和「复制到微信」按钮。月度总结只作为学生详情里的入口，不作为底部一级 Tab。

视觉上使用圆角卡片、柔和阴影、清晰层级、少量图标和克制配色。不要使用密集表格，不要使用复杂数据看板，不要使用大量彩色卡片，不要出现像未加载 CSS 的蓝色链接文档风格。

## 14. 验收标准

- 老师能在 3 步内开始生成反馈：选学生、加材料、点生成。
- 拍照/上传入口足够明显。
- 微信反馈结果页只突出可复制文本。
- 复制按钮比重新生成按钮更醒目。
- 页面整体友好轻快，但不幼稚。
- 色彩少而清晰，没有五颜六色的卡片。
- 不像飞书后台。
- 不像维基百科文本页。
- 移动端单手操作舒适。
