# 技术规范

## 固定技术栈

- Next.js App Router。
- TypeScript。
- Tailwind CSS。
- shadcn/ui 风格本地组件。
- lucide-react。
- Supabase Auth。
- Supabase Postgres。
- Vercel 部署。
- AI 调用通过服务端 API route 完成。

## 当前阶段技术边界

- Phase 1 使用 mock data。
- Phase 1 不接 Supabase。
- Phase 1 页面仍以 mock 展示为主；独立微信反馈 API route 可调用真实 AI，后续再接入 UI。
- Phase 1 登录页为临时免登录 UI。

## 目录约定

- `app/`：Next.js App Router 页面和 API route。
- `components/`：可复用组件。
- `components/ui/`：基础 UI 组件。
- `lib/mock/`：mock 数据。
- `lib/supabase/`：后续 Supabase 客户端、服务端和中间件。
- `src/agents/shared/model/`：provider-agnostic 模型配置、OpenAI-compatible client 和模型能力兼容层。
- `lib/ai/`：当前服务端 AI 工具、prompt 和 schema，只能被服务端模块或 API route 调用；后续应逐步迁入 Agent Harness。
- `docs/`：长期开发文档。
- `开发日记/`：每日开发记录。

## 安全规则

- 不允许在前端组件中读取或暴露服务端 API Key。
- `AI_API_KEY` 只能在服务端 API route 或服务端模块中使用。
- 默认模型提供方为 DeepSeek：`AI_PROVIDER=deepseek`、`AI_BASE_URL=https://api.deepseek.com`、`AI_MODEL=deepseek-v4-flash`。
- Supabase service role key 不允许出现在浏览器端代码。
- `.env.local` 不提交到仓库。
- `.env.example` 只放变量名，不放真实密钥。

## AI 调用规则

- 前端只能调用项目自己的 API route。
- API route 再调用 `src/agents/shared/model/` 的 provider-agnostic 模型层。
- 可以继续使用 OpenAI SDK 作为 OpenAI-compatible client，但 `baseURL` 必须读取 `AI_BASE_URL`，`apiKey` 必须读取 `AI_API_KEY`，模型必须读取 `AI_MODEL`。
- 业务 Agent 不应直接依赖某个厂商特性；严格 structured outputs、tool calling、JSON response mode 等能力必须在 shared/model 层做 capability check 和 fallback。
- AI 输出必须允许老师编辑后再保存或复制。
- 单次任务的显性 AI 输出只生成微信反馈，不在同一任务里生成月度总结、长篇报告或多个 AI 结果。
- 服务端可以在生成微信反馈时识别练习类型、题目信息、分数或表现、错误原因和后续建议，并沉淀结构化学习记录。
- `POST /api/ai/practice-recognition` 是练习图片识别接口，接收 1-9 张图片并返回老师可校正的结构化草稿。
- `POST /api/ai/wechat-feedback` 是单次微信反馈生成接口，优先基于老师校正后的 `correctedDraft` 生成可复制文案。
- 两个 AI API 只能在服务端通过 shared/model 层读取 `AI_API_KEY`；前端不得直接调用模型。
- 月度总结必须基于学生档案中已有学习记录、微信反馈和错题记录生成，不凭空生成正式总结。

## 验证命令

每次开发完成后优先运行：

```bash
npm run lint
npm run typecheck
npm run build
```

如果某个命令不可用，必须在开发日记中说明原因。
