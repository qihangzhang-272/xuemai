# 学脉月报设计说明

## 设计目标

月报不是普通总结文案，而是老师月度服务闭环的一部分：从已确认学习记录、学习材料分析、反馈状态和老师备注中，整理出可复用的学生/班级月度判断。

核心原则：

- 学生月报面向家长沟通，强调本月表现证据、一个主要进步、一个主要问题、下月跟进动作。
- 班级月报面向老师内部复盘，强调班课节奏、共性薄弱点、重点学生、分层安排和服务待办。
- 月报只能使用已入档或老师可核对的内容；未确认草稿不能直接进入最终月报。
- 月报必须区分“可给家长看”和“老师内部判断”。
- 学习材料分析输出的月报快照只是候选素材；只有老师确认后的快照副本才能进入月报聚合。

## 调研结论

形成性评价强调用学习证据调整后续教学，而不是只给分数或静态评价。因此学脉月报不应只做漂亮 PDF，而要回答老师每月真正关心的四个问题：

1. 这个学生/班级本月整体处在什么状态？
2. 哪些结论有证据，哪些还需要补材料？
3. 下月第一优先动作是什么？
4. 哪些内容可以给家长看，哪些只适合老师内部使用？

学生月报需要温和、具体、可转发；班级月报需要服务老师决策，不作为家长群发文案。

## 学生月报结构

1. 老师速读
   - 当前状态
   - 本月主要进步
   - 本月主要问题
   - 下月重点

2. 服务概览
   - 本月课次
   - 家长反馈次数
   - 已入档记录数
   - 学习材料分析数

3. 能力与习惯变化
   - 课堂理解
   - 独立完成
   - 表达习惯
   - 每一项必须有依据和下一步动作

4. 本月可用依据
   - 课堂记录
   - 学习材料分析
   - 家长反馈
   - 标注是否可写入家长版

5. 下月跟进安排
   - 3 条以内
   - 以可执行动作表达

6. 家长可读月报
   - 温和
   - 不承诺提分
   - 不贴负面标签
   - 可复制

7. 老师内部提醒
   - 需要补充的证据
   - 不适合写给家长的判断边界

## 班级月报结构

1. 老师复盘
   - 班级整体状态
   - 班课节奏
   - 共性卡点
   - 下月优先级

2. 服务指标
   - 班课次数
   - 学生人数
   - 待反馈人数
   - 月报就绪人数

3. 共性薄弱点
   - 薄弱点名称
   - 影响学生数
   - 证据
   - 教学动作

4. 学生分层跟进
   - 稳定推进
   - 需要跟进
   - 重点关注

5. 下月班课安排
   - 全班共性
   - 中段学生
   - 重点学生

6. 服务待办
   - 待补反馈
   - 已就绪学生月报
   - 分层练习草稿

7. 依据来源与边界
   - 班课记录
   - 学习材料分析
   - 反馈状态
   - 班级结论不能自动覆盖学生个人档案

## UI 承接方式

- 聊天区只显示月报 SkillCard 摘要。
- 点击“查看月报”后，在右侧侧聊打开完整月报详情。
- 右侧详情页保留底部追问输入框，老师可以围绕当前月报继续问，但侧聊内容不会自动入档。
- 导出按钮放在月报详情页顶部。

## 后续真实数据对接

后续接 Supabase 时，月报至少需要读取：

- 已确认 `student_learning_records`
- 已确认 `feedback_history`
- 已确认学习材料分析结果
- 月报素材池
- 班级成员与班课记录
- 待反馈和待入档状态

仍需保持：AI 草稿 → 老师确认 → 才能形成最终月报事实。

当前学生月报 mock 已使用确定性聚合器模拟真实路径：`createStudentMonthlyReportFromConfirmedSnapshots(...)` 读取老师确认后的学习材料快照、学习记录、家长反馈记录和老师备注，自动过滤未确认、非本学生和非本月素材。没有本月确认素材时，月报只能显示“依据不足”；缺少上月确认素材时，只能做有限比较，不能写成明确进步或退步。若只有学习记录、反馈或老师备注，而没有学习材料分析快照，可以生成服务型月报草稿，但逐题趋势仍必须提示依据不足。
