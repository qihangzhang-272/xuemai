# 学脉 Chat-first Skill Workflow UI 平移稿

本文件用于把当前对话中的产品结构和 UI 交互方向平移到学脉项目中，作为后续开发依据。

它不是评议文档，也不是开发流水账。

## 产品结构

学脉不是普通聊天工具，也不是 AI 工具箱。

学脉当前 Web 工作台应定位为 Chat-first Skill Workflow 系统：

- 会话：学生 / 班级工作台。
- 胶囊：Skill 工作流入口。
- 卡片：AI 工作流结果。
- 确认入档：长期记忆沉淀。

这意味着聊天框架只是承载形式，核心价值是把老师的课后工作流结构化、可确认、可沉淀。

## 页面结构

### 左侧会话区

- 学生显示为联系人。
- 班级显示为群聊。
- 会话列表承担工作对象切换，不承担复杂后台导航。

### 中间聊天区

- 普通输入保留自然语言。
- 老师可以像发消息一样记录课堂表现、错题、家长沟通和月报素材。
- AI 结果不以大面板展示，而以紧凑 SkillCard 进入聊天流。
- 系统事件以 ArchiveLog 形式进入聊天流。

### 底部 Skill 胶囊

Skill 胶囊是工作流入口，不是普通快捷按钮。

学生会话显示：

- 分析试卷
- 生成微信反馈
- 下次课建议
- 更新学习记录
- 生成月报
- 家长沟通

班级群聊显示：

- 记录班课
- 批量反馈
- 共性薄弱点
- 分层练习
- 班级月报
- 拆分到学生档案

老师工作台后续可显示：

- 今日待办
- 批量月报
- 备课助手
- 素材整理
- 续费跟进
- 服务复盘

### 右侧 ContextPanel

右侧上下文面板用于减少老师在多个页面之间跳转。

学生会话显示：

- 学生基础信息
- 当前状态
- 当前学习重点
- 家长关注点
- 最近 3 次记录
- 当前薄弱点
- 下次跟进
- AI 本次参考依据
- 待处理任务

班级群聊显示：

- 班级名称
- 学生人数
- 本周待反馈人数
- 本月待月报人数
- 共性薄弱点
- 需要关注学生
- 最近班课记录

宽屏显示 ContextPanel，窄屏自动隐藏，避免挤压聊天流。

## SkillCard 规范

统一 AI 工作流结果卡片，不再为不同功能各写一套大面板。

SkillCard 包含：

- Skill 类型：微信反馈、试卷分析、下次课建议、月报、批量反馈等。
- 状态：生成中、待确认、已复制、已发给家长、已入档、失败。
- 任务来源。
- AI 本次参考依据。
- 结构化结果预览。
- 操作按钮。

微信反馈卡片按钮：

- 复制微信反馈
- 改温和一点
- 改简洁一点
- 标记已发给家长
- 确认并入档
- 重新生成

试卷分析卡片按钮：

- 更新薄弱点
- 生成针对练习
- 生成微信反馈
- 加入月报素材
- 确认入档

按钮数量需要克制，优先保留当前状态下最有用的操作。

## 入档系统消息

老师点击确认并入档后，聊天流中插入 ArchiveLog 系统消息：

```txt
已入档到「学生姓名 > 课后反馈」，将作为下次备课和月报依据。
```

班级场景可对应为：

```txt
已入档到「班级名称 > 班课记录」，将作为下次备课和月报依据。
```

ArchiveLog 是普通聊天工具和学脉工作流系统的关键分界：AI 结果只有经过老师确认，才进入长期记忆。

## 输入框智能识别

老师输入自然语言后，系统可以先用 mock 形式识别内容类型：

- 课堂记录
- 普通备注
- 试卷 / 错题
- 家长沟通
- 月报素材

识别后给出快捷动作：

```txt
检测到这可能是一条课堂记录
```

按钮：

- 整理为学习记录
- 生成家长反馈
- 仅保存备注

后续接真实 Agent 时，识别逻辑应进入 shared context / routing 层，不应散落在 UI 组件里。

## 后续接入原则

1. SkillCard 后续应对齐 `agent_outputs`。
2. 确认入档后才写入 `feedback_history` 和 `student_learning_records`。
3. ArchiveLog 应对应一次明确的老师确认行为。
4. ContextPanel 只能展示可追溯数据，不应把 AI 草稿当作事实。
5. 学生画像更新只能作为建议出现，不能由 UI 或 AI 自动覆盖。
6. 后续新增 Wrong Question Agent、Monthly Report Agent、Batch Feedback Agent 时，应复用同一套 SkillCard 和入档机制。
