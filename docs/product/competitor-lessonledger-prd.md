# 竞品还原 PRD：独立老师课时管理系统

## 一、概述

**文档信息**

| 版本号 | 日期 | 作者 |
|---|---|---|
| V 1.0.0 | 2026-06-20 | 用户 |

**文档性质**

本 PRD 基于用户提供的竞品视频逐字稿、视频截图和关键帧观察整理，用于还原该竞品的产品结构、业务流程、页面职责和可实施功能规格。本文档描述的是竞品系统本身，不是学脉当前产品方案。

**竞品暂定名称**

文档内暂称该竞品为「LessonLedger 课时管理系统」。该名称仅用于 PRD 归档和描述，不代表竞品真实品牌名。

### 1. 需求背景

- **目标用户现状**：独立老师、小型教培老师、个人工作室老师日常需要同时管理排课、课时、考勤、课后反馈、家长沟通、学生成绩、薄弱点、学习报告、充值扣课和预约协调。
- **核心痛点**：老师的教学服务信息分散在微信、表格、日历、相册、纸质记录和个人记忆中，导致课程状态难追踪、家长反馈重复写、课时流水不透明、预约协调费时、学生学习情况难形成连续报告。
- **竞品解决思路**：以传统教务工作台为主入口，把课程表、课时流水、AI 反馈、家长门户、预约排课和学习报告统一到一个 Web 系统中。

**当前问题汇总**

| 问题点 | 问题描述 | 当前影响 |
|---|---|---|
| 课程状态分散 | 老师需要手动记住今日课程、已上课、缺席、取消、待反馈等状态 | 容易漏记课时、漏发反馈、影响课消和收入统计 |
| 班课考勤低效 | 班课需要逐个学生点名，缺席和取消状态需要单独记录 | 班课人数多时耗时，且事后难追溯 |
| 课后反馈重复劳动 | 每节课后都要给家长写反馈，内容需要结合课堂表现、作业和测验 | 老师重复写作成本高，反馈质量不稳定 |
| 家长沟通散落微信 | 家长看到反馈后可能继续追问，老师需要在微信里翻上下文 | 沟通与课程记录脱节，后续服务证据不完整 |
| 学生学习数据断裂 | 成绩、排名、薄弱点、课程记录、反馈分散保存 | 难生成阶段学习报告，也难支持续费沟通 |
| 课时和收款不透明 | 充值、扣课、撤销、消课流水需要单独记录 | 财务核对困难，容易产生家长争议 |
| 假期预约协调复杂 | 多个学生提出不同可上课时间，人工协调冲突成本高 | 老师排课效率低，容易出现时间冲突 |
| 家长端激活麻烦 | 家长需要绑定学生和老师，才能查看反馈、报告和预约 | 若没有邀请机制，账号开通与绑定成本高 |

### 2. 需求目标

**业务目标**

- 帮助独立老师在一个 Web 系统中完成今日课程处理、反馈生成、家长沟通和课时流水管理。
- 让家长能通过独立门户查看学生课程反馈、学习报告，并发起沟通和预约申请。
- 通过 AI 降低课后反馈与学习报告撰写成本，同时保留老师确认和复制发送动作。

**成功标准**

| 指标 | 当前状态 | 目标状态 |
|---|---|---|
| 今日课程处理完整率 | 建议默认值：老师依赖手动表格或记忆 | 每节课都能被标记为已上课、缺席、取消或待反馈 |
| 班课点名耗时 | 建议默认值：线下口头点名或表格记录 | 老师在 1 个页面内完成全班学生考勤并保存 |
| 课后反馈生成时间 | 建议默认值：每条 3-10 分钟人工撰写 | 老师输入课堂内容后，AI 生成可复制预览 |
| 家长沟通闭环率 | 建议默认值：微信里沟通，系统内不可追踪 | 家长可围绕某次反馈发起沟通，老师回复后状态变更 |
| 课时流水可追溯性 | 建议默认值：充值扣课记录分散 | 每一次充值、扣课、撤销都有流水记录 |
| 预约冲突处理 | 建议默认值：人工协调时间 | 系统自动识别冲突，并支持老师调整后通过预约 |

### 3. 需求范围

**包含**

- 教师端工作台：每周课程、每月收入、今日课程、推荐处理事项。
- 课程状态管理：已上课、学生缺席、取消、班课点名。
- AI 课后反馈：输入上课内容、课堂状态、作业、附件，生成反馈预览并复制或发送。
- 家长端门户：查看学生绑定老师、最近课程反馈、学习报告、发起沟通、预约上课。
- 学生资料：成绩、排名、考试记录、薄弱点、课程记录、收款和课时流水。
- 家庭邀请：老师生成待激活家长账号链接，家长打开后完成绑定。
- 学习报告：综合反馈、成绩、薄弱点生成阶段学习报告，确认保存后家长端可见。
- 预约排课：老师开放预约时段，家长提交预约，老师审核冲突并通过。
- 排课总表：查看课程表，拖动课程到新时间，并处理历史课程状态重置。
- 设置与版本：授权码、版本更新、数据保留说明。

**不包含**

- 复杂机构多校区管理。
- 完整在线支付闭环。
- 学生端 App。
- 自动发微信。
- 大型 CRM 销售系统。
- 复杂权限组织架构。
- 原生 iOS / Android App。
- AI 自动诊断最终学习结论而不经老师确认。

## 四、功能说明

### 功能 1：教师登录与授权

**功能描述**

老师可在登录页进入系统，并在设置中通过授权码使用版本更新能力，解决私有部署或试用版本无法统一升级的问题。

**用户流程**

```text
登录页
  ↓
输入账号和密码
  ↓
点击登录
  ├─ 成功 → 进入工作台
  ├─ 失败：账号或密码错误 → 显示错误提示，保留账号输入
  ├─ 失败：账号未授权 → 引导联系管理员或输入授权码
  └─ 网络异常 → 提示稍后重试

设置页
  ↓
输入授权码
  ↓
点击检查更新
  ├─ 授权码有效 → 显示可更新版本，点击更新
  ├─ 授权码无效 → 提示授权码错误
  └─ 更新失败 → 保留当前版本和数据
```

**状态机**

| 状态名称 | 进入条件 | 退出条件 | 用户可见表现 |
|---|---|---|---|
| 未登录 | 用户未持有登录态 | 登录成功 | 显示登录页 |
| 登录中 | 点击登录 | 成功或失败 | 登录按钮 loading |
| 已登录 | 登录成功 | 退出登录或登录态失效 | 进入工作台 |
| 授权未验证 | 未输入授权码 | 输入有效授权码 | 设置页显示未授权或试用状态 |
| 授权有效 | 授权码校验通过 | 授权过期 | 可检查更新 |
| 更新中 | 点击更新 | 成功或失败 | 显示更新进度 |

**字段规范**

| 字段名 | 类型 | 是否必填 | 长度限制 | 校验规则 | 错误提示 |
|---|---|---|---|---|---|
| 账号 | 文本 | 是 | 6-64 字符 | 支持手机号或邮箱格式 | 请输入正确的手机号或邮箱 |
| 密码 | 密码 | 是 | 8-32 字符 | 不能为空 | 请输入密码 |
| 授权码 | 文本 | 是 | 8-64 字符 | 仅允许字母、数字、短横线 | 授权码格式不正确 |

**文案规范**

| 场景 | 文案内容 |
|---|---|
| 空状态 | 请输入账号和密码登录 |
| 加载中 | 正在登录... |
| 操作成功 | 登录成功 |
| 操作失败 | 账号或密码错误 |
| 权限不足 | 当前账号未授权，请输入授权码或联系管理员 |
| 网络异常 | 网络异常，请稍后重试 |

**异常情况处理**

| 异常场景 | 触发条件 | 处理方式 | 用户反馈 |
|---|---|---|---|
| 登录态过期 | API 返回 401 | 清除本地登录态，跳转登录 | 登录已过期，请重新登录 |
| 授权码无效 | 授权校验失败 | 禁止更新版本 | 授权码无效，请检查后重试 |
| 更新失败 | 版本包下载或安装失败 | 回滚到旧版本 | 更新失败，已保留当前版本和数据 |

### 功能 2：首页数据总览

**功能描述**

## 七、关键业务规则

### 1. 课程状态规则

- 已上课课程默认生成待反馈任务。
- 学生缺席是否扣课由课程规则决定，老师必须可手动确认。
- 取消课程默认不扣课。
- 历史课程状态修改必须保留修改日志。

### 2. 反馈规则

- AI 只生成反馈草稿，老师需要复制或发送。
- 家长端只能看到老师已发送或确认公开的反馈。
- 反馈中不应出现“保证提分、完全不会、基础很差、不认真”等表达。
- 附件识别失败时，不阻断老师基于文字生成反馈。

### 3. 家校沟通规则

- 家长沟通必须关联学生。
- 从反馈详情发起的沟通必须关联对应反馈。
- 老师回复后，沟通状态变为已确认。
- 家长可继续追问，系统重新进入待回复。

### 4. 学习报告规则

- 报告必须基于已有反馈、成绩或薄弱点生成。
- 数据不足时显示“数据较少，仅供参考”。
- 未确认保存的报告不进入家长端。
- 同周期报告重复生成时，应提示覆盖或另存。

### 5. 预约规则

- 家长只能选择老师开放的时段。
- 系统必须排除已被课程占用的时间。
- 老师通过预约后，自动生成课程。
- 预约通过后与已有课程冲突时，必须回滚或阻止通过。

### 6. 课时流水规则

- 每次扣课、充值、撤销必须有流水。
- 不允许物理删除已影响余额的流水，只能生成反向调整。
- 课程重复扣课必须阻止。
- 欠费上课必须有老师确认。

## 九、非功能需求

### 1. 性能

| 场景 | 要求 |
|---|---|
| 工作台首屏加载 | 建议默认值：3 秒内展示主要数据 |
| AI 反馈生成 | 建议默认值：30 秒内返回，超时给重试 |
| 学习报告生成 | 建议默认值：60 秒内返回，超时允许后台生成 |
| 日历拖动响应 | 200ms 内有视觉反馈 |
| 家长端反馈列表 | 2 秒内加载最近五条记录 |

### 2. 数据安全

- 教师只能访问自己工作室内学生、课程和家长数据。
- 家长只能访问绑定学生的信息。
- AI 附件分析不得向家长暴露原始内部处理字段。
- 课时流水不可物理删除。
- 重要操作需记录操作人、时间和操作前后状态。

### 3. 可用性

- 关键操作必须支持撤销或反向流水。
- 表单必须保存草稿或离开提醒。
- AI 失败不能阻断老师手写反馈。
- 家长端页面应尽量简化，只展示反馈、报告、沟通、预约。

### 4. 兼容性

- 教师端优先支持桌面 Web。
- 家长端需支持手机浏览器。
- 图片附件支持 JPG、PNG、WEBP。
- PDF 附件建议默认支持单文件上传。

本节为产品分析补充，不属于竞品本身功能需求。

### 1. 值得借鉴

- 工作台必须能回答老师每天最关心的事情：今天几节课、谁待反馈、谁有风险、月报是否该生成、是否影响续费。
- 家长沟通必须关联具体反馈或课程，否则上下文会散。
- 学习报告不能只是一段 AI 总结，应该读取成绩、薄弱点、课程反馈和历史记录。
- 预约排课是独立老师真实高频痛点，尤其适合假期密集排课。
- 课时流水和课程状态强相关，不能只做聊天或 AI 反馈。

### 2. 不宜照搬

- 该竞品更像传统教务后台，入口偏表单、日历和管理页面；学脉当前定位是微信式 AI 教学工作台，不能被改造成后台。
- 家长端完整门户会显著增加产品复杂度；学脉若要做，应先保证老师端反馈闭环。
- 学习报告若直接给家长看，必须有老师确认和风险表达控制。
- 自动发送、自动诊断、自动入档都不适合教育场景直接开放。

### 3. 学脉可吸收的模块

| 竞品模块 | 学脉可吸收方式 |
|---|---|
| 工作台总览 | 放入“学脉助手”全局会话和今日待办 |
| 今日课程 | 作为老师待办和会话提醒，不做厚重教务后台 |
| AI 反馈 | 保留为聊天页 SkillCard |
| 家校沟通 | 先做微信反馈状态，不急于做家长端 |
| 学习报告 | 做分析详情页和月报详情页 |
| 预约排课 | 可作为后续老师服务管理模块 |
| 课时流水 | 可作为设置或学生档案中的轻量模块 |
