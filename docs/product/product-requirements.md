# 学脉完整产品需求文档（产品版 PRD）

> 本文档用于产品讨论、页面设计、版本排期和验收，内容聚焦客户、场景、页面、流程、功能、状态、版本、价值和范围边界。

## 一、产品概述

### 1. 文档信息

| 版本 | 日期 | 作者 | 状态 |
|---|---|---|---|
| V5.4.1 | 2026-08-06 | 用户 | 教师视角最终收敛后的当前产品基线 |

### 2. 一句话定位

学脉是面向小学到高中学科类独立老师和教培机构的微信式 AI 教学服务工作台。

它以学生为主线，把课堂记录、学习材料、学情分析、家长微信沟通、学生档案、月报和后续跟进连接起来，让老师一次记录、多处复用，让机构看到真实发生过的教学服务。

### 3. 核心产品形态

- 学生是联系人。
- 班级是群聊。
- 会话页是老师每天工作的入口。
- 老师可以在聊天中记录课堂、上传学生材料、接收家长微信消息。
- AI 通过明确的教学工作流生成卡片。
- 卡片是可处理的正式结果。
- 老师确认后，结果才进入学生长期档案。
- 同一条记录可继续用于家长反馈、学生月报和后续服务。
- 系统已经知道的学生、学科、时间和材料类型不要求老师重复填写，只有存在歧义时才确认。
- 老师每次输入只完成当前明确意图，不默认连续触发分析、反馈和入档。

核心闭环：

课堂或学生材料
→ AI 整理为当前意图对应的结果卡片
→ 老师一次检查结果和家长反馈
→ 老师确认发送；如需同时入档，再明确选择入档内容
→ 学生时间线和月报持续复用

家长沟通闭环：

家长微信消息进入学脉
→ 自动或人工归到对应学生
→ AI 整理事实、问题和建议回复
→ 老师检查并回复
→ 形成沟通记录
→ 需要时继续跟进

### 4. 产品版本

产品只设置两个正式版本：

| 版本 | 适用客户 | 核心区别 |
|---|---|---|
| 个人版 | 独立老师、个人名师、单账号工作室 | 一位老师独立管理学生、班级、反馈和家长沟通 |
| 机构版 | 多位成员共同服务学生的教培机构 | 增加成员分工、学生分配、协作、检查和机构视图 |

版本归类规则：

- 单一数据所有者、单账号使用的工作室归入个人版。
- 需要多个账号、多人协作或角色分工的工作室归入机构版。
- 不设置工作室版。
- 不设置集团版。
- 不做总部—区域—校区多层级管理。

### 5. 目标用户

| 用户 | 日常场景 | 核心需求 |
|---|---|---|
| 独立老师 | 一对一、小班课、微信服务家长 | 少整理、少切换、学生情况不丢失 |
| 授课老师 | 上课、批改、反馈、阶段总结 | 快速形成有依据的反馈 |
| 助教 | 收集材料、补充记录、跟进作业 | 与主讲老师使用同一份学生信息 |
| 班主任 | 家长沟通、问题跟进、阶段服务 | 知道发生了什么、应该怎么回复 |
| 课程顾问 | 家长疑问、服务回访、续费沟通 | 能看到真实教学服务，不靠临时找老师问 |
| 机构负责人 | 查看服务完成情况和异常 | 看服务状态、责任人和结果，不增加老师填表 |

### 6. 真实痛点

| 痛点 | 真实表现 | 后果 |
|---|---|---|
| 学生资料分散 | 作业、试卷、错题、课堂记录散落在微信、相册和表格 | 找不到、记不全、月底重复整理 |
| 课后反馈耗时 | 老师每次重新组织家长能看懂的话 | 反馈慢、表达不稳定 |
| 微信沟通与教学脱节 | 家长消息在微信，课堂事实在老师脑中 | 回复依赖记忆，容易口径不一致 |
| 单次 AI 没有长期价值 | 文案生成后即结束 | 无法形成学生连续档案 |
| 机构成员信息不同步 | 老师、班主任、课程顾问掌握的信息不同 | 重复询问、交接困难 |
| 服务价值不可见 | 机构只有排课、课时和收费记录 | 家长难感知过程，续费沟通缺少依据 |
| 功能堆积 | 竞品把排课、财务、薪酬等全部放进一个后台 | 老师操作负担加重，核心服务反而不清晰 |
| 缺少总体视图 | 学生、班级、反馈和跟进分散在不同入口 | 老师和负责人无法快速判断整体是否正常 |
| 重复批量操作 | 分班、分配老师、生成反馈和安排跟进需要逐个处理 | 学生数量增加后操作成本快速上升 |

### 7. 竞品启示

| 竞品优势 | 值得吸收的真实价值 | 学脉的产品表达 |
|---|---|---|
| 作业批改与错题分析 | 减少老师整理时间 | 只基于学生真实材料生成可核对分析 |
| 学习规划 | 把发现的问题转成近期方向 | 输出近期巩固方向，不做每日任务中心 |
| 上课反馈 | 让家长持续感知服务 | 从课堂记录直接生成可编辑反馈 |
| 家长沟通助手 | 帮助老师判断先核实什么、怎么回复 | 家长消息进入学生会话，AI 生成策略和回复草稿 |
| 续费提醒 | 避免服务和跟进遗漏 | 基于真实服务记录提醒跟进，不预测必然续费或流失 |
| 机构工作台 | 让负责人看到异常和责任人 | 展示待反馈、待跟进、逾期和服务完成情况 |

明确不照搬：

- 不把一次家长情绪变成永久家长标签。
- 不根据少量信息判断家长一定会退费或续费。
- 不自动替老师承诺提分、效果或续费结果。
- 不让 AI 未经老师确认直接回复家长。
- 不把产品做成大而全的通用教务后台。
- 不重复建设复杂财务、人事、工资和集团管理。

### 8. 产品目标

#### 用户目标

让老师在一个工作入口中完成：

1. 记录真实课堂和学生学习材料。
2. 获得有依据的分析和反馈草稿。
3. 直接处理家长微信消息。
4. 将确认过的结果沉淀为学生长期记录。
5. 在月报和后续沟通中继续复用。

#### 业务目标

1. 让会话页成为老师每天打开的教学服务入口。
2. 让同一条记录至少被反馈、档案、月报或沟通中的两个环节复用。
3. 验证个人版和机构版是否都愿意为“教学服务连续性”长期使用。
4. 让机构在不增加老师填报的情况下看见服务进度和异常。
5. 让高频重复操作可以批量完成，同时保留每位学生的独立结果和处理状态。

### 9. 成功标准

| 指标 | 目标 |
|---|---|
| 有效材料形成可处理结果 | 不低于 90% |
| 长期档案由老师确认 | 100% |
| 家长反馈状态清晰 | 100% 可区分待反馈和已反馈 |
| 同一记录被多处复用 | 不低于 70% |
| 直连微信沟通可追踪 | 100% 可看到家长、学生、回复人、时间和结果 |
| 高优先级家长问题按时完成 | 不低于 90% |
| 内测老师认为节省整理时间 | 不低于 70% |
| 已知学生、学科和记录时间重复填写 | 0 次；仅在信息有歧义时确认 |
| 典型课后记录与反馈闭环 | 老师只需一次内容检查和一次完成确认 |
| 教学反馈与家长回复状态 | 100% 可区分，不混用状态 |
| 机构成员重复询问和重复录入 | 明显下降 |
| 可批量处理的高频事项 | 不低于 80% 可在对象列表多选或管理页完成 |
| 总览发现异常后的处理闭环 | 不低于 90% 可直接进入对应事项 |

### 10. 当前版本范围

#### 当前版本包含

- 个人版和机构版。
- 学生、班级和家长关系。
- 微信式聊天工作台。
- 会话中的学生、当前学科和记录时间自动带出，只有歧义时要求老师确认。
- 课堂文字记录和学生材料上传。
- 学习记录卡片和学情分析卡片。
- 分析详情页。
- 微信反馈生成、编辑、复制、确认发送和标记已发。
- 在同一个“检查并反馈”面板中检查结果和反馈正文，并可选是否同时入档。
- 家长微信消息进入学生会话。
- 家长消息分析、回复草稿和后续跟进。
- 老师确认入档和学生时间线。
- 学生详情页。
- 学生月报。
- 班级公共记录和逐学生反馈。
- 机构成员分工、学生分配和服务状态查看。
- 个人总览和机构总览。
- 学生、班级、负责人、反馈、月报和跟进的批量管理。

#### 当前版本不包含

- 老师备课、教案和课件制作。
- 学生开放式答题助手。
- 每日打卡、每日任务和任务派发中心。
- 完整题库和全自动批改平台。
- 复杂排课。
- 完整收费、会计、工资和人事系统。
- 自动营销和批量骚扰式消息。
- 集团版和多层组织管理。
- 未经老师确认的家长消息发送。
- 永久学生或家长负面标签。
- 保证提分、保证报名或保证续费。

## 二、产品结构

### 1. 整体结构

产品围绕五个主要入口展开。页面只是对学生、关系、事件、证据、结论产物和未完成责任的不同观察与操作方式：

| 一级入口 | 产品定位 | 主要用户 |
|---|---|---|
| 工作台 | 查看整体状态、异常、提醒和下一步 | 个人老师、机构负责人、教务 |
| 会话 | 日常教学和家长沟通主入口 | 所有老师与机构服务成员 |
| 学生 | 查看学生当前状态和长期记录 | 老师、班主任、课程顾问 |
| 班级 | 查看班级成员和公共教学记录 | 授课老师、助教 |
| 我的（个人版）/管理（机构版） | 个人版管理个人偏好、微信和账号；机构版管理成员、分配、交接和设置 | 个人老师、教务、机构管理员 |

产品组合规则：

- 原“总览”和“待处理”合并为工作台，同时回答“整体是否正常”和“下一步处理什么”。
- 批量管理不是独立业务领域，而是学生、班级、工作台清单和管理页中的多选操作模式。
- 续费和报告属于学生服务过程中的阶段或产物，不建立并列一级入口。
- AI 分析、反馈和报告以会话中的确定工作流及结果卡片出现，不建立 AI 工具箱。
- 普通会话输入默认生成学习记录卡片并自动保留在会话；老师明确选择“生成反馈”或上传学生材料后，才进入对应工作流。
- 学生会话自动带出学生和当前科目，记录时间默认当前时间；可确定的信息不再次要求老师选择。
- 个人版保留五个一级入口，但默认工作重心是工作台和会话；第五个入口显示为“我的”，不展示成员分配、交接等机构能力。

桌面端采用微信式三栏：

- 左侧：学生、班级和家长会话。
- 中间：聊天内容、输入区和结果卡片。
- 右侧：学生状态、分析详情或报告详情。

移动端采用逐层进入：

- 会话列表。
- 会话页面。
- 结果详情。
- 关键操作固定在底部。

### 2. 页面清单

| 层级 | 页面 | 页面职责 |
|---|---|---|
| 一级 | 工作台 | 查看整体服务状态、异常、提醒和待处理责任 |
| 一级 | 会话页 | 记录、上传、接收微信消息、处理卡片 |
| 一级 | 学生页 | 搜索学生并进入学生详情 |
| 一级 | 班级页 | 查看班级、成员和近期记录 |
| 一级 | 我的（个人版）/管理（机构版） | 个人版管理账号、偏好和微信；机构版增加成员、角色、数据来源和批量操作 |
| 二级 | 学生详情页 | 查看当前状态、近期关注和时间线 |
| 二级 | 分析详情页 | 查看一次完整学情分析 |
| 二级 | 月报详情页 | 查看和编辑月度反馈 |
| 二级 | 历史沟通详情页 | 查看家长原话、老师回复和处理结果 |

| 弹窗 | 发送确认 | 确认家长、最终正文和发送动作 |
| 弹窗 | 确认入档 | 选择要进入学生档案的内容 |
| 弹窗 | 消息认领 | 将未匹配的家长微信消息归到学生 |

### 3. 页面职责

| 页面 | 用户要完成的事 | 主要内容 | 空状态 |
|---|---|---|---|
| 工作台 | 快速判断整体服务是否正常并处理下一步 | 状态、异常、提醒、待处理、快捷入口 | 当前没有需要处理的事项 |
| 会话页 | 完成一次教学记录或家长沟通 | 会话、消息、输入、材料、卡片 | 选择学生或班级开始 |
| 学生详情页 | 快速了解学生最近情况并返回会话继续处理 | 基础信息、关注点、近期记录、时间线、家长关系 | 暂无已入档记录 |
| 班级详情页 | 了解班级和成员情况 | 班级信息、成员、公共记录、个体反馈 | 暂无班级记录 |
| 我的（个人版）/管理（机构版） | 管理低频配置；机构管理员完成规模化动作 | 个人偏好、微信、账号；机构版增加成员、分配、交接、数据来源和批量操作 | 暂无需要管理的内容 |
| 分析详情页 | 检查一次完整分析 | 概览、依据、问题、方向、家长反馈 | 当前材料不足以形成分析 |
| 月报详情页 | 完成月度总结 | 本月记录、变化、重点、反馈正文 | 本月可用记录不足 |
| 历史沟通详情页 | 回看一次家长沟通 | 家长原话、事实核对、回复、负责人、结果 | 暂无沟通记录 |

### 4. 功能与页面映射

| 功能 | 入口 | 处理过程 | 结果 |
|---|---|---|---|
| 总体查看 | 工作台 | 选择个人/班级/机构范围和时间 | 状态卡、异常和待处理清单 |
| 课堂记录 | 会话页 | 输入课堂内容 | 学习记录卡片；确认入档后进入学生时间线 |
| 材料分析 | 会话页 | 上传学生材料 | 学情分析卡片、分析详情页 |
| 家长反馈 | 结果卡片 | 编辑、发送确认 | 会话页、历史沟通详情 |
| 家长消息处理 | 微信消息/会话页 | 事实核对、回复草稿 | 历史沟通详情、工作台待跟进 |
| 确认入档 | 结果卡片/分析详情 | 确认入档弹窗 | 学生详情页、时间线 |

| 批量管理 | 对象列表多选/管理页 | 筛选、勾选、确认批量动作 | 批量结果汇总、逐项结果明细 |

## 三、用户角色与产品权限

### 1. 个人版

个人版只有一位数据所有者。

老师可以：

- 创建和管理自己的学生、班级和家长关系。
- 记录课堂、上传学生材料。
- 处理微信反馈和家长消息。
- 确认学生档案和生成月报。
- 查看全部自己的服务记录。

### 2. 机构版

| 角色 | 主要职责 | 默认可见范围 |
|---|---|---|
| 机构负责人 | 查看整体服务情况和异常 | 机构汇总状态；原始内容按需要查看 |
| 教务/管理员 | 管理成员、学生分配和服务关系 | 机构成员、学生和分配信息 |
| 授课老师 | 完成教学记录和反馈 | 自己负责的学生和班级 |
| 助教 | 补充材料和记录 | 被分配的学生和班级 |
| 班主任 | 家长沟通和后续跟进 | 自己负责的学生和家长沟通 |
| 课程顾问 | 家长回访和续费沟通 | 被分配的学生和家长 |

产品规则：

- 机构负责人看服务状态，不默认围观所有聊天原文。
- 成员只能处理自己被分配的学生或事项。
- 每条反馈、沟通和入档记录都能看到实际处理人。
- 成员离开机构后，学生记录仍归机构继续服务。
- 批量操作只能覆盖成员原本可以管理的学生、班级和事项。
- 批量操作前必须展示影响数量；执行后必须展示成功、失败和未处理明细。

## 四、核心用户旅程

### 1. 独立老师课后服务

老师进入学生聊天
→ 输入本节课内容和学生表现
→ 系统生成学习记录卡片并自动保留在会话
→ 老师可以直接离开，也可以选择“检查并反馈”或“加入学生档案”
→ 需要反馈时，老师在同一处理面板检查记录和反馈正文
→ 直接发送家长微信，或复制后标记已发
→ 如需同时入档，老师再勾选“同时加入学生档案”并选择保留内容
→ 已入档内容进入学生详情，并用于月报积累

异常情况：

- 信息太少：提醒老师补充，不生成空泛结论。
- 反馈中出现过度承诺：提醒修改后再发送。
- 家长尚未连接：保留复制发送方式。
- 老师暂时不处理：进入待反馈。
- 老师只想记录：学习记录卡片自动保留在会话，不要求额外操作，也不自动生成反馈或入档。

### 2. 学生材料分析

老师上传有学生作答或批改痕迹的材料
→ 系统先判断是否具备分析条件
→ 生成学情分析卡片并自动保留在会话
→ 老师进入分析详情查看完整结果
→ 老师可以生成家长反馈，或单独选择加入学生档案
→ 需要反馈时，可在发送确认中勾选“同时加入学生档案”

异常情况：

- 空白试卷或纯教材：不判断学生能力。
- 材料模糊：提示重新上传。
- 信息不足：只描述看得见的内容，不补造结论。
- 多名学生材料混在一起：要求老师确认对应学生。

### 3. 家长微信沟通

家长消息进入学脉
→ 系统归到对应学生
→ AI 分为已知事实、需要核实、建议回复和后续动作
→ 仅在存在待核实项时，请老师补充课堂事实
→ 编辑并确认回复
→ 如需继续处理，个人版只设置跟进时间；机构版设置负责人和跟进时间
→ 完成后记录结果

异常情况：

- 无法识别对应学生：进入消息认领。
- 只有家长主观判断：先向老师核实，不直接判断教学效果。
- 投诉或退费争议：提醒负责人介入。
- 同一问题已有跟进：合并查看，避免重复处理。

### 4. 机构协作服务

授课老师完成课堂记录
→ 班主任收到待反馈提醒
→ 班主任结合课堂记录回复家长
→ 课程顾问可查看已确认的服务结果
→ 负责人查看是否按时完成

产品价值：

- 老师不用重复向班主任解释。
- 班主任不需要临时拼凑家长回复。
- 课程顾问基于真实服务沟通，而不是只看课时和收费。
- 负责人看到异常和责任人，而不是要求全员填日报。

### 5. 工作台与批量操作

老师或负责人进入工作台
→ 查看学生、班级、反馈、家长沟通、待处理和跟进的整体状态
→ 点击异常或数字进入对应清单
→ 在对应清单或管理页筛选并勾选对象
→ 选择批量动作
→ 查看影响范围并确认
→ 查看总体结果和逐项明细

个人老师典型批量动作：

- 批量生成班级逐学生反馈草稿。
- 批量生成月报草稿并进入逐项检查队列。
- 批量调整普通跟进事项的完成时间。

机构管理员典型批量动作：

- 批量加入班级或调整班级。
- 批量分配负责老师、班主任或课程顾问。
- 批量设置学生服务状态。
- 批量生成课堂反馈草稿、月报草稿或普通跟进事项。
- 批量调整负责人和计划完成时间。
- 批量归档已结束且无待处理事项的学生。

产品边界：

- 批量生成不等于批量确认。
- 个性化反馈仍为每位学生独立结果。
- 未检查的个性化反馈不能直接批量发送。
- 有待反馈、待跟进或未完成服务的学生不能直接批量归档。
- 高风险家长沟通不能被普通批量操作关闭。

## 六、功能说明

### 功能 1：学生与班级聊天

#### 功能描述

老师用联系人和群聊方式管理学生与班级。所有教学记录、材料、结果卡片和家长沟通都围绕对应会话展开。

#### 用户流程

进入会话页
→ 选择学生或班级
→ 查看近期消息和状态
→ 输入记录、上传材料或处理待办

分支：

- 没有学生：引导创建第一位学生。
- 没有班级：可继续只使用学生会话。
- 无权查看：返回有权限的会话列表。

#### 状态

| 状态 | 表现 |
|---|---|
| 正常 | 显示聊天内容和输入区 |
| 有待反馈 | 会话显示待反馈标记 |
| 有待回复 | 会话显示家长消息标记 |
| 有待跟进 | 会话显示跟进标记 |
| 暂无记录 | 显示开始记录引导 |
| 已归档 | 不出现在默认列表，可搜索查看 |

#### 主要输入

| 内容 | 规则 | 提示 |
|---|---|---|
| 学生姓名 | 必填，避免只使用昵称 | 请输入学生姓名 |
| 年级 | 必填 | 请选择年级 |
| 学科 | 至少一项 | 请选择学科 |
| 班级名称 | 创建班级时必填 | 请输入班级名称 |
| 班级成员 | 可后续补充 | 请选择班级成员 |

#### 关键文案

| 场景 | 文案 |
|---|---|
| 空状态 | 选择一位学生或班级开始记录 |
| 创建成功 | 已创建学生会话 |
| 加载失败 | 暂时无法打开会话，请稍后重试 |
| 无权查看 | 你无法查看这位学生的记录 |

#### 异常处理

- 同名学生：同时展示年级、班级和负责老师供确认。
- 学生已归档：提示恢复或只读查看。
- 班级成员变更：保留历史记录，不改写过去反馈。

### 功能 2：课堂记录

#### 功能描述

老师在学生或班级聊天中输入课堂内容、学生表现、作业情况和需要关注的事项，AI 整理为学习记录卡片。

#### 用户流程

选择会话
→ 输入课堂内容
→ 自动带出学生、当前学科和记录时间
→ 生成学习记录卡片并自动保留在会话
→ 老师无需保存操作，可选择“检查并反馈”或“加入学生档案”
→ 选择“检查并反馈”时，在同一面板检查记录和反馈正文；需要时再勾选同时入档

分支：

- 内容过少：提示补充。
- 当前会话包含多个科目且无法判断：只询问一次本次学科。
- 班级记录：先形成公共记录，再选择是否补充个体差异。
- 老师不满意：继续编辑，不进入正式档案。

#### 状态

| 状态 | 表现 |
|---|---|
| 编辑中 | 输入内容尚未提交 |
| 整理中 | 显示正在整理课堂记录 |
| 待检查 | 卡片已生成，等待老师处理 |
| 已保留 | 记录已自动保留在会话，但尚未进入长期档案 |
| 待入档 | 可进入学生长期记录 |
| 已入档 | 已出现在学生时间线 |

#### 主要输入

| 内容 | 是否必填 | 规则 |
|---|---|---|
| 课堂内容 | 是 | 至少包含一个具体教学内容 |
| 学生表现 | 否 | 只写本次可观察表现 |
| 作业情况 | 否 | 不把未完成直接解释为态度问题 |
| 记录时间 | 系统带出 | 默认当前时间，老师需要时修改 |
| 学科 | 系统优先带出 | 使用会话当前科目；无法确定时再让老师选择 |

#### 关键文案

| 场景 | 文案 |
|---|---|
| 空状态 | 记录今天学了什么、学生表现和作业情况 |
| 整理中 | 正在整理课堂记录 |
| 成功 | 学习记录已整理并保留在会话 |
| 信息不足 | 再补充一点具体课堂内容，结果会更准确 |
| 保存失败 | 记录未保存，输入内容已保留 |

#### 异常处理

- 出现长期定性：改为“本次课堂观察”。
- 班级公共内容被误当个体表现：公共内容可以保留为课堂背景；只有写入个体表现时才要求选择对应学生。
- 重复提交：只保留一条，提示老师查看已有记录。

### 功能 3：学生材料分析

#### 功能描述

老师上传学生已作答、订正、批改或记录过的学习材料，获得一次完整学情分析。

#### 用户流程

进入学生会话
→ 上传材料
→ 自动带出学生，并判断学科和材料类型
→ 存在歧义时请老师确认一次
→ 判断是否具备分析条件
→ 生成学情分析卡片
→ 查看分析详情
→ 处理反馈与入档

分支：

- 材料清晰且有学生痕迹：生成完整结果。
- 看不清：提示重新上传。
- 没有学生痕迹：只说明材料类型，不判断学生能力。
- 材料不完整：明确缺少什么。

#### 状态

| 状态 | 表现 |
|---|---|
| 待上传 | 尚未选择材料 |
| 分析中 | 展示处理进度 |
| 待检查 | 分析结果已生成 |
| 证据不足 | 不生成能力结论 |
| 需补充材料 | 展示需要补充的内容 |
| 分析失败 | 保留材料，可重新分析 |

#### 主要输入

| 内容 | 是否必填 | 规则 |
|---|---|---|
| 学生 | 系统带出 | 使用当前学生会话；从其他入口上传时才要求选择 |
| 材料 | 是 | 支持照片或文件 |
| 学科 | 系统优先判断 | 结合当前科目和材料内容判断；不确定时确认 |
| 材料类型 | 系统优先判断 | 作业、试卷、错题、笔记、练习；不确定时确认 |
| 补充说明 | 否 | 可说明考试背景或老师关注点 |

#### 关键文案

| 场景 | 文案 |
|---|---|
| 空状态 | 上传学生作业、试卷、错题或笔记 |
| 分析中 | 正在整理这份学生材料 |
| 成功 | 学情分析已生成，请老师检查 |
| 证据不足 | 当前材料不足以判断学生表现 |
| 需补充 | 请补充更清晰或更完整的学生作答 |
| 失败 | 本次分析未完成，材料已保留 |

#### 异常处理

- 空白试卷：不生成薄弱点和错因。
- 多名学生材料：要求重新选择或拆分。
- 单次材料出现严重结论：改为本次表现，不形成长期标签。
- 结果与老师观察冲突：允许老师修改或不入档。

### 功能 4：结果卡片与分析详情

#### 功能描述

所有正式 AI 结果以卡片出现。卡片展示结论摘要、状态和下一步；完整内容进入分析详情页。

#### 卡片包含

- 卡片名称。
- 对应学生或班级。
- 输入来源。
- 生成时间。
- 结果摘要。
- 待反馈/已反馈状态。
- 待入档/已入档状态。
- 检查并反馈、加入学生档案、查看详情等操作。

#### 用户流程

结果生成
→ 会话页出现卡片并自动保留
→ 老师查看摘要
→ 老师无需保存操作，可选择“检查并反馈”或“加入学生档案”
→ 需要时查看完整详情

分支：

- 结果未完成：只显示进行状态。
- 结果证据不足：禁止反馈和入档。
- 内容被修改：保留原版本和当前版本供查看。
- 老师未明确选择生成反馈：不自动追加反馈、月报或下次课建议。

#### 状态

| 状态 | 表现 |
|---|---|
| 生成中 | 卡片显示进行中 |
| 可处理 | 展示摘要和操作 |
| 待反馈 | 突出反馈操作 |
| 已反馈 | 显示实际处理时间 |
| 待入档 | 展示入档入口 |
| 已入档 | 展示已进入时间线 |
| 需补充 | 展示需要补充的材料 |
| 失败 | 展示重新处理入口 |

#### 关键文案

| 场景 | 文案 |
|---|---|
| 空状态 | 结果会以卡片形式出现在这里 |
| 进行中 | 正在生成结果 |
| 成功 | 结果已生成，请检查 |
| 内容更新 | 已保存新的编辑版本 |
| 失败 | 本次结果未生成，可重新处理 |

#### 异常处理

- 卡片摘要和详情不一致：提示内容已更新，以最新版本为准。
- 失败卡片误出现发送按钮：隐藏所有正式操作。
- 一张卡片信息过多：摘要收起，完整内容进入详情页。

### 功能 5：微信反馈与确认发送

#### 功能描述

系统根据课堂记录或学情分析生成家长可读的微信反馈。老师可以编辑、复制、直接发送或手工标记已发。

“教学反馈”是老师基于课堂或学生材料主动发给家长的阶段说明；“家长回复”是老师回应一条进入学脉的家长消息。两者状态和记录分开，避免老师混淆。

#### 用户流程

生成反馈草稿
→ 老师进入“检查并反馈”
→ 在同一面板检查学习结果和反馈正文
→ 选择处理方式

分支：

- 直接发送：确认家长和最终正文即可发送；“同时加入学生档案”默认不勾选，不阻塞发送。
- 复制发送：复制到微信；老师点击“我已发送”即可完成反馈，也可主动勾选“同时加入学生档案”。
- 同时入档：只有老师主动勾选后，才展开入档内容选择并进行二次确认。
- 暂不处理：保持待反馈。
- 内容不合适：修改后再处理。

#### 状态

| 状态 | 表现 |
|---|---|
| 待反馈 | 已有草稿，尚未完成反馈 |
| 编辑中 | 老师正在修改 |
| 确认发送 | 展示家长和最终正文 |
| 发送中 | 暂时不可重复操作 |
| 发送失败 | 仍保持待反馈 |
| 结果待确认 | 提醒老师不要重复发送 |
| 已反馈 | 显示发送或标记时间 |

#### 主要输入

| 内容 | 是否必填 | 规则 |
|---|---|---|
| 反馈正文 | 是 | 清楚、具体、家长可理解 |
| 接收家长 | 直接发送时是 | 必须与学生关系明确 |
| 处理方式 | 是 | 直接发送或复制发送；标记已发只用于复制后的完成确认 |
| 同时加入学生档案 | 否 | 默认不勾选；不影响发送或标记已发 |
| 本次入档内容 | 勾选同时入档时是 | 由老师逐项选择；未勾选则保持待入档 |
| 修改说明 | 否 | 仅供老师自己回看 |

#### 关键文案

| 场景 | 文案 |
|---|---|
| 空状态 | 选择生成反馈后会出现反馈草稿 |
| 编辑成功 | 反馈已保存 |
| 复制成功 | 已复制，发送后请标记已发 |
| 发送确认 | 请确认接收家长和最终内容；如需可同时加入学生档案 |
| 发送成功 | 已发送给家长 |
| 发送失败 | 本次未发送，你可以重试或复制发送 |
| 结果待确认 | 正在确认发送结果，请勿重复发送 |

#### 异常处理

- 家长未绑定：不能直接发送，保留复制方式。
- 同一内容重复发送：提醒该版本已处理。
- 出现“保证提分”等承诺：阻止发送并提示修改。
- 老师误标已发：不能删除历史，可创建修正记录。

### 功能 6：确认入档与学生时间线

#### 功能描述

AI 结果默认只是草稿。老师选择并确认后，才进入学生长期记录。

确认入档可以在结果详情中单独完成，也可以在“检查并反馈”面板中由老师主动勾选“同时加入学生档案”。该选项默认不勾选，发送反馈不要求老师先处理入档；一旦勾选，仍必须明确选择内容并确认，不能自动入档。

#### 用户流程

打开结果卡片、详情或“检查并反馈”面板
→ 选择确认入档
→ 查看将要保存的内容
→ 勾选需要保留的部分
→ 确认
→ 学生详情和时间线更新

分支：

- 老师不同意结论：取消或修改。
- 内容已入档：提示无需重复操作。
- 后续需要修正：创建新的更正记录，保留原历史。

#### 状态

| 状态 | 表现 |
|---|---|
| 待入档 | 结果可保存但尚未确认 |
| 确认中 | 展示将保存的内容 |
| 已入档 | 出现在时间线 |
| 已更正 | 展示后续更正内容 |
| 不入档 | 保留本次结果但不进入长期档案 |

#### 主要输入

| 内容 | 是否必填 | 规则 |
|---|---|---|
| 入档内容 | 是 | 老师逐项选择 |
| 适用时间 | 系统带出 | 使用本次课堂或材料日期，老师需要时修改 |
| 老师备注 | 否 | 可说明为什么保留或修改 |

#### 关键文案

| 场景 | 文案 |
|---|---|
| 确认提示 | 确认后将进入学生长期记录 |
| 成功 | 已加入学生时间线 |
| 重复 | 这条内容已经入档 |
| 失败 | 本次未入档，原结果仍保留 |

#### 异常处理

- 入档内容包含长期负面标签：提醒改为客观阶段描述。
- 来源已失效：不允许新入档。
- 重复点击：只产生一条记录。

### 功能 7：学生详情页

#### 功能描述

学生详情页用于了解学生状态，不承担复杂工作操作。

#### 页面内容

- 学生基础信息。
- 家长关系。
- 当前学习状态。
- 近期关注点。
- 高频薄弱点。
- 最近课堂和材料记录。
- 最近反馈状态。
- 待跟进事项。
- 学生时间线。
- 月报入口。
- 返回学生会话的明确入口。

#### 不在此页出现

- 上传材料。
- 逐题分析。
- 大量操作按钮。
- 每日任务和打卡。
- 复杂机构管理。

#### 状态

| 状态 | 表现 |
|---|---|
| 新学生 | 展示开始记录引导 |
| 正常服务 | 展示近期状态和时间线 |
| 有待反馈 | 顶部提示未完成反馈 |
| 有待跟进 | 展示最近待处理家长事项 |
| 已暂停 | 保留历史，弱化新增入口 |
| 已归档 | 只读查看，可恢复 |

#### 关键文案

| 场景 | 文案 |
|---|---|
| 空状态 | 还没有已入档的学习记录 |
| 有待反馈 | 有一条学习反馈尚未处理 |
| 有待跟进 | 有一项家长沟通需要继续跟进 |
| 加载失败 | 暂时无法加载学生详情 |

### 功能 8：家长消息分析与回复

#### 功能描述

家长微信消息进入学生会话后，系统帮助老师区分事实、需要核实的问题、建议回复和后续动作。

家长消息回复不使用“待反馈/已反馈”状态：回复一条家长来信使用“待回复/已回复”；如果回复后仍有后续事项，再显示“待跟进”。

#### 用户流程

收到家长消息
→ 归到对应学生
→ 识别沟通场景
→ 展示已知事实和待核实项
→ 生成回复草稿
→ 存在事实缺口时老师补充；没有缺口时直接编辑并回复
→ 记录实际结果

分支：

- 无法匹配学生：进入消息认领。
- 缺少课堂事实：先提醒向授课老师核实。
- 投诉或退费：进入高优先级处理。
- 需要后续动作：个人版负责人自动为当前老师且不展示选择，只设置跟进时间；机构版设置负责人和时间。

#### 状态

| 状态 | 表现 |
|---|---|
| 待认领 | 尚未确认对应学生 |
| 待核实 | 缺少必要事实 |
| 待回复 | 已有回复草稿 |
| 回复中 | 正在确认回复 |
| 已回复 | 保存最终回复和时间 |
| 待跟进 | 还有后续事项 |
| 已完成 | 已回复且所有后续事项结束，本次沟通关闭 |
| 已放弃 | 明确不再继续处理 |

#### 主要输入

| 内容 | 是否必填 | 规则 |
|---|---|---|
| 对应学生 | 系统优先匹配 | 无法确定时必须人工选择 |
| 对应家长 | 系统优先匹配 | 与学生关系明确；无法确定时确认 |
| 沟通场景 | 系统优先判断 | 日常、效果疑问、投诉、退费、续费、其他；不确定时确认 |
| 实际回复 | 回复时是 | 保存老师最终采用内容 |
| 跟进负责人 | 机构版需要跟进时是 | 个人版默认当前老师且隐藏；机构版必须明确到人 |
| 跟进时间 | 需要跟进时是 | 必须有具体日期 |

#### 关键文案

| 场景 | 文案 |
|---|---|
| 待认领 | 请确认这条消息属于哪位学生 |
| 待核实 | 当前缺少课堂或学习依据，请先核实 |
| 草稿生成 | 已整理回复建议，请老师检查 |
| 回复成功 | 已回复家长 |
| 高优先级 | 该情况需要负责人及时介入 |
| 完成 | 本次沟通已完成 |

#### 异常处理

- 将家长情绪写成人格标签：改为“本次沟通状态”。
- 将家长说法直接当成学生事实：标记为待核实。
- 过度承诺：阻止回复并提示修改。
- 同一事件重复跟进：合并到已有事项。

### 功能 9：待处理与跟进

#### 功能描述

集中展示老师和机构成员今天需要完成的反馈、回复和跟进，不做复杂任务管理。

工作台不平铺所有业务状态，只回答“现在需要做什么”。已反馈、已回复和已入档默认收进完成记录；待入档作为次级提醒，不与待反馈、待回复争夺首屏注意力。

#### 列表类型

- 待反馈。
- 待回复。
- 待核实。
- 待跟进。
- 已逾期。
- 我负责的。
- 待入档（次级）。

#### 用户流程

进入工作台待处理区
→ 选择事项
→ 回到对应学生会话或详情
→ 完成处理
→ 列表更新

#### 状态

| 状态 | 表现 |
|---|---|
| 待处理 | 显示负责人和时间 |
| 处理中 | 显示当前处理人 |
| 已完成 | 移入完成记录 |
| 已逾期 | 突出显示 |
| 已取消 | 保留取消原因 |

#### 关键文案

| 场景 | 文案 |
|---|---|
| 空状态 | 当前没有待处理事项 |
| 即将到期 | 今天需要完成 |
| 已逾期 | 已超过计划处理时间 |
| 完成 | 已完成处理 |

#### 异常处理

- 负责人离开机构：重新分配。
- 学生权限发生变化：转给新的负责人。
- 重复事项：合并展示。

### 功能 10：学生月报

#### 功能描述

系统使用本月已入档的课堂记录、材料分析和家长反馈生成月报草稿。“已入档”是月报可复用素材的唯一口径，避免老师不清楚哪些内容会进入月报。

#### 用户流程

从学生会话、学生详情或工作台进入月报
→ 默认打开当前月份并自动汇总已入档记录
→ 老师需要时切换月份或排除个别记录
→ 生成月报草稿
→ 老师编辑
→ 保存草稿、确认定稿或进入“检查并反馈”发送家长

分支：

- 记录充分：生成完整月报。
- 记录较少：生成简版总结并提示依据有限。
- 没有记录：不生成空泛月报。
- 班级批量生成：为每位学生生成独立草稿并进入逐项检查队列，不逐个进入学生详情。

#### 月报内容

- 本月学习内容。
- 主要表现。
- 已确认的进步。
- 当前关注点。
- 近期巩固方向。
- 下月沟通重点。
- 家长微信版摘要。

#### 状态

报告内容状态：

| 状态 | 表现 |
|---|---|
| 可生成 | 本月有足够记录 |
| 素材不足 | 提示缺少内容 |
| 草稿 | 等待老师编辑 |
| 已定稿 | 月报内容已经老师确认 |
| 已更正 | 有后续修正版 |

家长反馈状态沿用统一口径：

| 状态 | 表现 |
|---|---|
| 待反馈 | 已有月报反馈正文，尚未发送或标记已发 |
| 已反馈 | 已发送家长或由老师标记已发 |

#### 关键文案

| 场景 | 文案 |
|---|---|
| 空状态 | 本月已入档记录不足，暂不能生成月报 |
| 生成中 | 正在整理本月学习情况 |
| 成功 | 月报草稿已生成 |
| 依据有限 | 本月记录较少，以下内容仅反映已入档情况 |

#### 异常处理

- 跨学生混入记录：只保留当前学生。
- 用未入档草稿生成月报：排除未入档内容，并提示可先在原记录中确认入档。
- 没有上月记录却写“明显进步”：删除比较表达。

### 功能 11：班级记录与逐学生反馈

#### 功能描述

老师先记录一节班课的公共内容。公共内容默认作为当前班级全体成员的课堂背景，但不等同于每位学生的个体表现；老师只需为有差异的学生补充个体表现，再生成逐学生独立反馈。

#### 用户流程

进入班级会话
→ 记录公共课堂内容
→ 默认选中当前班级全体成员
→ 排除缺席或本次不需要反馈的学生
→ 按需选择少数学生并补充个体表现
→ 展示“将为 N 位学生生成反馈草稿”并确认
→ 生成逐学生反馈草稿
→ 分别检查和处理

#### 状态

| 状态 | 表现 |
|---|---|
| 公共记录草稿 | 尚未生成个体反馈 |
| 可补充个体 | 可为有差异的学生补充表现，不强制逐人填写 |
| 批量生成中 | 逐个出现结果 |
| 部分完成 | 已完成与失败学生分开显示 |
| 全部完成 | 每位学生都有独立结果 |

#### 关键文案

| 场景 | 文案 |
|---|---|
| 空状态 | 记录本节班课的公共内容 |
| 个体补充 | 哪些学生需要补充个体表现？没有差异可直接继续 |
| 生成确认 | 将为 N 位学生生成反馈草稿，请确认本次名单 |
| 部分失败 | 部分学生反馈未生成，可单独重试 |
| 成功 | 已生成逐学生反馈草稿 |

#### 异常处理

- 把公共内容当成所有学生个体表现：只作为课堂背景。
- 缺席学生被默认选中：老师可在生成前排除，系统保留本次排除结果。
- 一键发送全班：不提供未经逐条检查的批量发送。
- 单个学生失败：不影响其他学生结果。

### 功能 12：机构协作

#### 功能描述

机构版让授课老师、助教、班主任、课程顾问和负责人围绕同一学生协作。

#### 主要能力

- 成员和角色。
- 学生与班级分配。
- 反馈和跟进负责人。
- 待处理汇总。
- 服务完成情况。
- 历史处理人和交接。

#### 用户流程

管理员添加成员
→ 分配角色和学生
→ 成员处理自己负责的服务
→ 负责人查看完成情况和异常
→ 需要时重新分配或交接

#### 状态

| 状态 | 表现 |
|---|---|
| 待加入 | 成员尚未进入机构 |
| 正常 | 可处理分配范围 |
| 暂停 | 暂时不能新增处理 |
| 已离开 | 不再访问机构内容 |
| 待交接 | 有未完成事项需要转移 |
| 已交接 | 新负责人接手 |

#### 关键文案

| 场景 | 文案 |
|---|---|
| 空状态 | 添加第一位成员开始协作 |
| 分配成功 | 已分配学生和服务范围 |
| 无权查看 | 你无法查看这位学生的内容 |
| 待交接 | 该成员仍有未完成事项 |
| 交接完成 | 学生和待处理事项已转交 |

#### 异常处理

- 学生无人负责：进入机构异常列表。
- 多人同时处理同一反馈：显示正在处理的人。
- 成员离开但仍有待办：必须完成交接。

### 功能 13：老师偏好

#### 功能描述

老师可设置常教学段、学科和反馈表达习惯，使草稿更贴近自己的日常方式。

#### 主要设置

- 常教学段。
- 常教学科。
- 反馈语气：简洁、温和、专业。
- 常用称呼。
- 默认反馈长度。
- 是否优先显示家长版摘要。

#### 规则

- 个性化不能改变事实。
- 个性化不能加入贬损、诊断和结果保证。
- 机构模板可提供参考，老师仍可编辑最终内容。

### 功能 14：工作台与批量操作

#### 功能描述

工作台帮助个人老师和机构负责人快速判断整体服务是否正常、还有哪些责任未完成；对象列表和管理页中的批量模式帮助用户一次处理多个学生、班级或服务事项，避免重复逐个操作。

个人版和普通授课老师只看到与教学服务直接相关的批量动作；成员分配、交接、批量调整服务状态和批量归档只向机构管理员开放。

个人版总览重点：

- 学生总数与服务中学生。
- 今日新增课堂记录与最近课堂。
- 待反馈、待回复和待跟进。
- 本月已有记录和可生成月报的学生。
- 长时间没有新记录的学生。

机构版总览重点：

- 在读学生、班级和服务成员。
- 今日新增课堂记录及其反馈完成情况。
- 待反馈、待回复、待跟进和已逾期。
- 家长高优先级问题。
- 学生无人负责和成员待交接。
- 本月反馈、月报和阶段报告完成情况。

总览展示原则：

- 先显示需要处理的异常，再显示普通数字。
- 每个数字和异常都可以进入对应清单。
- 个人版只展示老师自己的范围。
- 机构负责人可看整体，普通成员只看自己负责的范围。
- 总览不以聊天数量和在线时长评价老师。
- 当前版本不依赖排课数据，不展示“应上但未记录”的课程完成率；总览中的课堂数量只统计实际产生的课堂记录。

#### 用户流程

进入工作台
→ 选择查看范围和时间
→ 查看状态、趋势和异常
→ 点击数字或异常进入清单
→ 勾选需要处理的对象
→ 选择批量动作
→ 查看影响数量和可能被跳过的项目
→ 确认执行
→ 查看成功、失败和未处理明细

分支：

- 没有异常：展示正常状态和近期变化。
- 没有可操作权限：只显示可查看内容。
- 部分对象不符合条件：执行符合条件的部分，并列出未处理原因。
- 批量结果包含个性化内容：先生成独立草稿，等待逐项检查。

#### 支持的批量对象与动作

| 对象 | 个人版/授课老师 | 机构管理员 |
|---|---|---|
| 学生 | 批量加入自己的班级、生成普通服务草稿 | 加入/调整班级、分配负责人、调整服务状态、归档 |
| 班级 | 生成班级逐学生反馈草稿 | 分配老师、设置班主任、调整服务状态、生成反馈草稿 |
| 课堂记录 | 选择月报素材、生成逐学生反馈草稿 | 同个人版，并可调整负责人 |
| 家长反馈 | 批量生成草稿、进入逐项检查队列 | 同个人版，并可调整负责人 |
| 月报 | 批量生成草稿、进入逐项检查队列 | 同个人版，并可查看团队完成情况 |
| 跟进事项 | 调整自己负责事项的完成时间、标记普通事项完成 | 分配负责人、调整完成时间、标记普通事项完成 |

不支持的批量动作：

- 未经检查批量发送个性化家长反馈。
- 批量确认学生长期档案。
- 批量关闭投诉、退费和安全类高优先级沟通。
- 批量归档仍有待反馈、待回复或待跟进的学生。
- 批量把家长情绪或一次表现写成长期标签。

#### 状态

| 状态 | 表现 |
|---|---|
| 未选择 | 显示可筛选对象和批量动作说明 |
| 已选择 | 显示已选数量和可用动作 |
| 待确认 | 展示影响范围、变化内容和跳过规则 |
| 处理中 | 展示总体进度，暂不可重复提交 |
| 全部完成 | 显示成功数量和查看结果入口 |
| 部分完成 | 分开展示成功、失败和跳过明细 |
| 已取消 | 未产生变化，保留原筛选条件 |

#### 主要筛选和输入

| 内容 | 是否必填 | 规则 |
|---|---|---|
| 查看范围 | 是 | 个人、我的学生、班级或机构范围 |
| 时间范围 | 否 | 今日、本周、本月或自定义时间 |
| 学生状态 | 否 | 服务中、暂停、即将结束、已归档 |
| 班级 | 否 | 可多选 |
| 负责人 | 否 | 可按授课老师、班主任或课程顾问筛选 |
| 服务状态 | 否 | 待反馈、已反馈、待跟进、已逾期等 |
| 批量动作 | 执行时是 | 只能选择当前对象支持的动作 |
| 目标值 | 视动作而定 | 例如目标班级、负责人、状态或完成时间 |

#### 关键文案

| 场景 | 文案 |
|---|---|
| 总览空状态 | 暂无可展示的服务数据，先创建学生或完成一条记录 |
| 总览正常 | 当前没有需要立即处理的异常 |
| 批量空状态 | 当前筛选下没有可批量处理的内容 |
| 选择提示 | 已选择 N 项，请选择批量操作 |
| 确认提示 | 本次操作将影响 N 项，其中 M 项可能被跳过 |
| 全部完成 | 已完成 N 项批量操作 |
| 部分完成 | 已完成 N 项，M 项未处理，请查看明细 |
| 权限不足 | 你只能处理自己负责范围内的内容 |
| 操作失败 | 本次批量操作未完成，原有内容未改变 |

#### 异常处理

- 选择对象类型混杂：只显示共同支持的动作，或提示分开处理。
- 部分学生无权限：不处理这些学生，并列出数量。
- 批量归档包含未完成事项：跳过对应学生并提示先完成服务。
- 批量生成个性化反馈：每位学生生成独立草稿，不合并成同一内容。
- 批量操作中途取消：已完成项目保留，未开始项目停止，并展示明细。
- 同一对象同时被其他成员处理：提示当前负责人，避免覆盖。
- 操作范围过大：提醒进一步筛选，并分批完成。

## 七、统一状态与产品规则

### 1. 四个核心状态

| 状态 | 含义 |
|---|---|
| 待反馈 | 已有家长反馈草稿，尚未完成 |
| 已反馈 | 老师已发送或确认已发 |
| 待入档 | 有内容可进入长期记录，尚未确认 |
| 已入档 | 老师已确认进入学生档案 |

单条结果卡片的状态显示顺序：

已反馈 > 待反馈 > 已入档 > 待入档。

如果一条结果已经反馈但尚未入档：

- 主状态显示“已反馈”。
- 次状态显示“待入档”。

老师可见状态规则：

- 一位学生或一个会话聚合多条结果时，只要存在新的未完成事项，就优先显示未完成责任；历史已反馈不能覆盖新的待反馈。
- 会话列表和工作台优先显示尚未完成的责任，不同时堆叠全部状态。
- 会话列表最多显示一个主状态和一个次状态。
- 主状态回答“现在要做什么”：待反馈、待回复、待跟进或异常。
- 待入档只作为次状态；已反馈、已回复、已入档默认进入完成记录。
- 工作台排序优先级为：异常/已逾期 > 待回复/待反馈/待跟进 > 待入档 > 已完成。

### 2. 家长沟通状态

| 状态 | 含义 |
|---|---|
| 待认领 | 还未确认对应学生 |
| 待核实 | 缺少必要教学事实 |
| 待回复 | 已有草稿，尚未回复 |
| 已回复 | 已完成本次回复 |
| 待跟进 | 还有后续事项 |
| 已完成 | 本次沟通结束 |
| 已放弃 | 明确不继续处理 |

其中：

- “已回复”表示老师已经回复家长，但可能仍有待跟进事项。
- “已完成”表示回复和全部后续事项均已结束。

### 3. 异常状态

- 证据不足。
- 需补充材料。
- 分析失败。
- 发送失败。
- 发送结果待确认。
- 家长未绑定。
- 无权查看。

异常状态出现时，优先告诉用户“为什么不能继续”和“下一步能做什么”。

### 4. 产品内容规则

- 没有学生真实学习痕迹，不判断学生能力。
- 单次材料只描述本次表现，不生成长期标签。
- 家长说法和老师确认事实分开。
- AI 草稿和老师最终版本分开。
- 复制不等于已反馈。
- 教学反馈和家长消息回复是两类不同记录，不共用“已反馈/已回复”状态。
- AI 不得未经老师确认直接回复家长。
- 老师确认后才能入档。
- 月报只使用已入档记录；“已确认记录”在月报场景中统一指已入档记录。
- 机构汇总不替代学生原始服务记录。
- 已知学生、学科、时间和材料类型不重复要求填写；只有存在歧义时才确认。
- 普通文字输入默认生成学习记录草稿，不自动串行生成反馈、月报或下次课建议。
- 上传材料只触发材料判断与分析确认，不因为上传自动发送反馈或写入档案。
- 个人版跟进负责人固定为当前老师并隐藏；机构版只有需要协作时才要求选择负责人。
- 班级公共记录默认只作为全班课堂背景，不能自动写成每位学生的个体表现。

### 5. 禁止表达

禁止：

- 基础很差。
- 完全不会。
- 不认真。
- 很严重。
- 家长难沟通。
- 情绪型家长。
- 保证提分。
- 保证报名。
- 肯定续费。
- 一定会退费。

推荐：

- 从本次课堂看。
- 从当前材料看。
- 目前可以确认的是。
- 还需要向老师核实的是。
- 建议近期重点关注。
- 需要结合后续练习继续观察。

## 八、产品指标

### 1. 激活

- 创建第一位学生。
- 完成第一条课堂记录。
- 生成第一张结果卡片。
- 完成第一次家长反馈。
- 确认第一条学生档案。

### 2. 日常使用

- 每周活跃老师数。
- 每位老师每周完成的教学服务闭环数。
- 每周处理的家长消息数。
- 待反馈平均完成时间。
- 高优先级家长问题按时完成率。
- 总览异常被点击并进入处理的比例。
- 每周使用批量管理的活跃用户比例。
- 单次批量操作平均处理数量。
- 从输入课堂记录到完成家长反馈的平均人工操作次数。
- 已知学生、学科、时间由老师重复修改或补填的比例。
- 生成学习记录后未继续反馈或入档的比例；卡片自动保留不计为中断。

### 3. 质量

- 无学生痕迹材料正确拒绝率。
- 老师修改反馈的比例和主要原因。
- 老师放弃入档的比例和原因。
- 家长消息需要补充事实的比例。
- 被老师纠正的长期标签和过度承诺数量。
- 批量操作全部完成率和部分完成率。
- 批量生成的个性化反馈逐项检查完成率。

### 4. 复用价值

- 一条记录被反馈、档案、月报和沟通复用的次数。
- 月报使用已入档记录的覆盖率。
- 机构成员重复询问次数变化。

## 九、产品验收标准

### 1. 核心体验

- 老师可从学生或班级聊天完成课堂记录和材料上传。
- 在学生会话中，学生、当前学科和记录时间默认带出；只有存在歧义时才要求老师选择。
- 普通文字输入默认只生成学习记录，不自动追加反馈、月报、任务或入档动作。
- 学习记录卡片生成后自动保留在会话，不要求老师再次点击“保存”。
- 所有正式结果以卡片出现。
- 会话页只展示摘要，完整分析进入详情页。
- 家长微信消息能进入对应学生会话。
- 工作台能展示个人或机构整体状态、异常、待处理和快捷入口。
- 总览中的数字和异常能进入对应清单。
- 批量管理支持筛选、勾选、影响确认、执行进度和结果明细。
- 批量操作中不符合条件的项目能被跳过并说明原因。
- 个性化反馈批量生成后仍保持逐学生独立结果和检查状态。
- 无法对应学生的消息进入人工认领。
- 老师能编辑并确认回复家长。
- 教学反馈使用待反馈和已反馈；家长来信回复使用待回复和已回复，两套状态不混用。
- “检查并反馈”在同一面板中完成结果和反馈正文检查；“同时加入学生档案”默认不勾选，不阻塞发送。
- 入档无论单独完成还是与反馈一起完成，都必须由老师明确选择并确认。
- 列表和工作台每个对象最多展示一个主状态和一个次级状态；待入档不遮挡待回复、待反馈和待跟进。
- 同一学生存在历史已反馈和新的待反馈时，会话列表和工作台必须优先显示待反馈。
- 学生详情页以查看状态为主，不堆复杂操作。
- 学生详情页提供明确的返回学生会话入口。
- 月报可从学生会话、学生详情或工作台进入，只使用已入档记录；报告内容状态和家长反馈状态分别展示。
- 班级反馈默认覆盖当前班级成员，老师可排除缺席学生，只需为有差异的学生补充个体表现。

### 2. 个人版

- 一位老师可以独立完成学生管理、教学记录、家长反馈和月报。
- 不出现机构专属的复杂管理页面。
- 个人版第五个一级入口命名为“我的”，不使用机构后台式的“管理”。
- 不向个人老师展示成员分配、责任人交接和机构服务状态批量操作。
- 个人版跟进负责人默认当前老师且不展示选择，只要求填写跟进时间。
- 支持批量生成逐学生独立的班级反馈草稿和月报草稿，但每位学生仍需分别检查。
- 单账号工作室无需选择第三种版本。

### 3. 机构版

- 成员有清晰角色和负责范围。
- 老师、班主任和课程顾问围绕同一学生协作。
- 负责人能看到待反馈、待跟进、逾期和责任人。
- 成员离开后可以交接学生和未完成事项。
- 负责人查看汇总，不要求老师重复填报。
- 负责人能在工作台查看机构服务状态，并在管理页或对象列表的批量模式中分配学生和负责人。

### 4. 内容边界

- 空白试卷不能生成学生能力判断。
- 单次材料不能自动形成长期负面标签。
- 家长情绪不能形成永久家长画像。
- AI 不能未经老师确认直接回复家长。
- 产品不承诺提分、报名和续费结果。

## 十、版本路线

### 阶段 1：个人老师可信闭环

- 学生与班级聊天。
- 课堂记录。
- 学生材料分析。
- 结果卡片和分析详情。
- 微信反馈。
- 确认入档。
- 学生详情。

阶段目标：老师能独立完成一次从记录到家长反馈和学生沉淀的完整服务。

### 阶段 2：微信家长沟通

- 家长微信消息进入学生会话。
- 消息认领。
- 事实核对。
- 回复草稿。
- 老师确认回复。
- 待跟进和历史沟通。

阶段目标：老师不需要在学脉和微信之间重复搬运信息。

### 阶段 3：月报与班级

- 已入档记录复用。
- 学生月报。
- 班级公共记录。
- 逐学生反馈。
- 个人总览。
- 课堂反馈和月报草稿的批量生成与检查队列。

阶段目标：从单次服务升级为连续服务。

### 阶段 4：机构版

- 成员和角色。
- 学生分配。
- 服务负责人。
- 待处理汇总。
- 服务检查和交接。
- 机构总览。
- 学生、班级、负责人和跟进事项的批量管理。

阶段目标：机构多人协作但不增加老师重复填报。

## 十一、最终产品结论

学脉当前最重要的产品形态不是“教培功能大全”，而是一个真正进入老师日常工作的微信式教学服务入口。

它要做到：

- 老师愿意每天打开。
- 课堂和学生材料只记录一次。
- 家长微信消息直接进入学生服务上下文。
- AI 帮助整理，但不替老师承担最终判断。
- 反馈、档案、月报和跟进相互连接。
- 个人老师足够轻，机构协作足够清楚。
- 学生数量增加后，老师和机构仍能通过工作台与对象列表的批量模式高效处理。

任何新增功能都必须先回答三个问题：

1. 是否减少老师重复整理？
2. 是否让学生服务记录更连续？
3. 是否让家长反馈或机构协作更可信？

如果不能明显改善这三件事，就不进入当前产品。
