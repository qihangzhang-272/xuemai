# 会议、PRD 与原前端如何结合

## 依据和取舍

用户 2026-09-06 最新要求：“把开会聊的内容和 PRD 还有前端结合好，不用做得太复杂”；微信直连“先不管这个”。会议白板前半段介绍旧教学助手的出题/批改及早期设想，最后的 MVP 边界明确止于生成可复制粘贴到微信的家长学情反馈，网页端、本地数据、独立打包。

本次按最终 MVP 约束演示范围，用原 PRD V5.4.1 规范核心交互，不将全文所有 P1 都扩建进演示。PRD 原文件保持不变，不能声称全量 PRD 已交付。

| 内容 | 本次处理 |
| --- | --- |
| 原前端 | 沿用 `components/xuemai-workbench`、原资源、配色与组件；必要调整入口、文案和行为 |
| 核心主线 | 选学生 → 记录课堂或上传材料 → 检查完整结果 → 生成/编辑/复制家长反馈 |
| PRD 核心规则 | 姓名/年级/至少一学科；没有学习痕迹不推断能力；反馈不用先入档；入档选内容并确认；复制和已发独立 |
| 次级能力 | 学生档案、更正历史、单学生月报素材选择、班级共同记录、偏好 |
| 本次撤下 | 备课/日报新建，未接通的批量跟进/分配、假日程、财务 |
| 本次不扩建 | 机构权限、家长消息收件箱、复杂跟进、批量月报/班级反馈、微信直连、小程序 |
| 独立性 | 独立仓库、接口、SQLite 和配置；复用已复制的通用代码，不连接旧项目业务服务 |

原始前端核对记录：`2026-09-06-原前端文件核对.csv`。完整 PRD 缺口基线：`2026-09-06-PRD对照审计.md`。后者是全量规划审计，不应与本次简洁演示范围混为一谈。

## 验收

- 类型检查、ESLint 通过；5 个回归文件共 71 项通过。
- 真实模型 HTTP 验收通过 31 次接口检查：课堂整理、反馈、月报、上传材料分析、过期版本拒绝、跨账号隔离、禁用旧接口、拒绝备课/日报新建。
- 真实材料验收通过 5 类样本：PDF 学生作答、PNG 订正为 observed；空白 PNG、DOCX 教案、PPTX 课件为 insufficient，不能据此生成学生能力结论。
- 浏览器实际操作：学生年级缺失时不能建档；建档后进入会话；未入档时生成/编辑/复制反馈；只勾选“观察事实”入档后，反馈仍为待发；月报可排除素材，全部排除时禁用生成；月报可编辑、定稿、生成家长摘要并单独标记已发。
- 桌面与 390 × 844 窄屏人工截图检查，完整正文可滚动、表单按钮可操作，记录详情未发现横向溢出。浏览器最终 error/warn 日志为空。
- 演示中“已发”是对合成学生记录测试手工标记，没有向真实家长发送消息。
- AI 草稿曾出现“专注”“掌握扎实”等未给出的评价，已加强生成规则，并实际验证新生成的家长摘要；老师检查与编辑入口仍保留，不能宣称 AI 输出永远无需核对。

运行证据保存在本机 `output/http-smoke.json`、`output/material-smoke.json`、`output/prd-demo-2026-09-06/`。生产构建和交付版本见同目录验收报告。
