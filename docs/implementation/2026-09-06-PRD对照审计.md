## 5. 内容与数据规则的额外缺口

| 规则 | 当前核对 | 验收要求 |
| --- | --- | --- |
| 复制不等于已反馈 | 已分离复制和已发动作 | 继续保留；真实发送、复制标记与失败结果分别记录。 |
| 老师确认后才入档 | 已有显式动作与快照 | 增加逐项内容选择，不能把整段默认全收当作内容确认已完成。 |
| 无学习痕迹不判断能力 | 有共用提示与证据类型校验 | 混合材料、模糊材料、空白题目仍需基于真实材料验收，不能只看提示词。 |
| 过度承诺阻止发送 / 回复 | 当前主要依靠模型提示，`sent` 分支没有内容校验 | 明确检测和修改提示；不能将有安全提示词等同于该验收项已通过。 |
| 已反馈显示实际时间 | 当前没有独立 `sentAt`；卡片时间常使用记录创建/更新时间 | 记录实际发送或标记时间，后续其他操作不能改写这一事实。 |
| 历史更正保留关联 | 当前锁定正文并要求另建，但没有明确更正关联 | 新版本可追溯旧版本，并显示已更正。 |
| 实际用户指标 | 未完成真实教师试用采样 | PRD 的 90% 成功、70% 节省时间等是待验证目标；合成 Demo 和自动化测试不证明这些指标。 |

## 6. 接下来按什么验收，避免再次偏离

1. **先纠正 P0 动线与范围**：D01–D06；先保留记录，再可选检查反馈/入档。保留原组件与视觉，不通过隐藏必需入口来降低复杂度。验证一条记录不入档也能反馈、入档可逐项选择、用户可只记录后离开。
2. **补齐个人版完整服务**：家长关系、月报入口与素材、跟进、班级逐学生反馈、批量检查队列。验证所有批量结果有独立学生和状态，空范围、缺席、失败均可处理。
3. **完成微信接入与机构协作**：PRD 已定义产品要求，真实微信收发还需可用接入渠道与账号配置，不能用本地模拟状态宣称接通。机构角色、权限与交接必须用不同账号验证。
4. **按 PRD §九逐条验收**：每项记录界面入口、步骤、接口/持久化结果和证据；未通过写明原因。当前 61 项测试是旧实现的局部回归，不是完整 PRD 的验收清单。

以上是修复次序，不是缩减范围。尚未实现的 P1 仍在交付清单里。当前版本只能表述为“部分核心流程可运行的独立 Demo”，不能以“完整按照 PRD 做完”对外演示或验收。
