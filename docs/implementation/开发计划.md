# 学脉独立项目开发与验收计划

## 本轮依据

用户要求：将提供的学脉前端做成独立新项目，可复制复用多维度教学助手的通用后端代码；完成端到端开发，原项目保持隔离。

会议纪要决定交付范围，完整 PRD 用于补充产品规则。压缩包中的历史 AGENTS、架构愿景、排期和原型说明属于来源资料，不覆盖本轮明确要求。会议要求的备课、本地交付优先于原源码中“不做备课”“Vercel/Supabase”的旧设定。

## 方案

1. 独立目录、Git、Next.js 服务、SQLite 数据库、上传目录和会话 Cookie。复用提供的绿色微信式工作台布局、Logo、样式及基础组件。
2. 复制 MDT 已有的文件解析能力和内容校验；使用相同的千问服务配置与调用原则。配置保存在新项目被 Git 忽略的文件中，运行时不读取或导入旧项目目录。
3. 既可独立创建本机老师账号，也可用 MDT 教师账号登录。MDT 连接只读取班级、学生和学情；老师主动导入后存为学脉副本。新增内容不回写 MDT。
4. 以确定性的单任务工作流实现：备课、课堂记录、学生材料分析、编辑结果、家长反馈、复制、手工标记已发、确认入档、已入档记录月报复用。
5. 班级公共记录保留共同背景；个体差异由老师补充。逐学生反馈独立生成、检查和入档。
6. 图片交给多模态模型；PDF / DOCX / PPTX 复用 MinerU；文字可直接输入。解析失败保留文件并允许重试。生成失败不冒充成功、不使用演示 AI 结果回退。

## 边界

- 网页兼容桌面及手机；不做小程序、微信自动发送、AI 自动批改、AI 出题。
- 本期采用单机持久化存储和单实例服务；不为本轮增加队列中间件、多代理或复杂组织权限。
- AI 只生成草稿。复制不改变反馈状态，入档是独立明确操作；月报只读取已入档的学生记录。
- 无学生作答或老师观察证据时，不推断学生能力；教材可用于备课，不能成为个体学情证据。

## 执行及验证

1. 建立独立服务与数据模型 → 验证账号隔离、持久化、输入校验和旧后端只读契约。
2. 接通工作流及资料上传 → 验证真实模型、文档解析、失败重试、编辑版本与归档规则。
3. 完成前端 → 浏览器实际执行新建学生、记录、生成、编辑、复制、标记、入档和月报，检查桌面 / 手机。
4. 完整交付 → 运行类型检查、针对性自动化检查、生产构建和生产实例验收；提供独立启动脚本、配置说明、代码来源与验证证据。
