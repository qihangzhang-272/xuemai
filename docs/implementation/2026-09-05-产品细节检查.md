## 检查方法

按“选择学生或班级 → 输入课堂表现／添加材料 → 阅读结果 → 编辑 → 家长反馈 → 确认入档 → 报告 → 通知与设置”逐步操作。将页面复现与实际调用代码对照，使用明确标记的合成学生材料验证生成。另检查了 390 × 844 窄屏、保存请求失败、空记录范围和切换会话。

## 已执行的验证

- `npm run typecheck`、`npm run lint`、`npm test`：通过，本期 52 项测试。
- `npm run build`：通过，采用生产模式启动原版工作台。
- 浏览器：快捷按钮不覆盖输入；不同学生草稿隔离并恢复；公式分段显示；失败保存保留编辑并可重试；真实通知筛选和定位；学生报告选择及空范围引导。
- 真实模型：新建合成课堂记录，检查并编辑正文后确认入档，再按学生与日期生成日报。日报来自指定日期的已确认记录，不混入草稿。
- 窄屏：390 × 844；页面宽度为 390，没有页面级横向溢出，四行输入展开到 96 像素，报告弹窗及按钮可见。
- 扩展原版历史测试：运行时 520 / 525 通过，5 项失败均涉及 Windows 的 `\\` 与预期 `/` 路径差异，分布在 `server-only-boundary.test.ts` 和 `student-learning-material-analyzer-evaluation-artifact-bundle-file.test.ts`。这些研究／原型测试不等于当前工作台功能；本次未以忽略失败的方式宣称全库通过。

浏览器检查包含键盘可访问的选择控件与错误提示，但未做完整读屏器验收；手机检查是浏览器窄屏模拟，未验证真机软键盘。

## 仍需处理或尚未支持

1. **老师／机构资料编辑**：注册表单中的机构、城市、教学场景尚未完整持久化。本次将工作室页改成真实资料查看，没有冒充编辑已经完成。
2. **刷新恢复**：侧边追问和未发送的会话草稿目前仅在当前页面保留；刷新或关闭页面不会恢复。跨会话草稿保留不等于本地持久化。
3. **编辑离开保护**：保存失败已保留正文，但未保存编辑时直接切换整个页面，仍缺少离开提醒或草稿恢复。
4. **未实现能力**：定时提醒、自动反馈、微信直发、批量学生反馈、班级记录自动拆到个人档案和机构协作，不能因为原型出现过入口就认定可用。本次隐藏了未接通的快捷操作，表单里保留的是安排信息。
5. **历史内容**：此前已保存的 AI 草稿和老师已确认正文没有批量改写。新的生成要求能改善文案，但每份教学内容仍需老师检查；旧稿可在未入档时重新生成。

后续优先补齐资料保存与草稿恢复，再处理批量任务。当前结论是上述关键问题已修复和复测，不是整个 PRD 已完成或所有细节都已没有问题。
